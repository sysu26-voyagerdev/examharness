# 知识图谱构建报告

这份报告说明 `seed/knowledge.json`（知识点与前置关系）与 `seed/knowledge-fusion.json`
（真题统计与共现证据）是怎么来的、可靠到什么程度、哪里不可靠。

一句话：**图谱是脚本从真实材料里算出来的产物，不是手写的配置**；但它的精度受材料限制，
下面「诚实清单」那一节请当作使用前必读。

---

## 1. 输入（以及哪些进了 Git）

| 输入 | 位置 | 进 Git | 用来干什么 |
|---|---|---|---|
| 课标 2022 / 2025 修订的条目 | `data/curriculum/课标*.requirements.jsonl` | 否 | 每个知识点**凭什么存在**（哪一页、哪一条）、所属领域路径 |
| 课标示例 | `data/curriculum/课标*.examples.jsonl`、`corpus/extracted/*.jsonl` | 否 | 部分知识点的示例依据（例 64…） |
| 中考真题结构统计 | `data/zhenti/structure.json`（183 份去重卷、4571 道题） | 否 | 题型分布、分值、支持卷数、**共现** |
| 真题原文 | `data/zhenti/txt/*.txt` | 否 | 只在需要人工看一眼时用（公式大多在 docx 里是图片，抽取时丢了） |
| 人工审定表 | `scripts/graph-nodes/*.mjs` | 是 | 哪个知识点存在、前置是谁、年级章节、匹配词 |

`scripts/graph-nodes/*.mjs` 是**唯一允许人写的东西**：它是"存在性"与"前置"的审定表。
表里**不许写任何统计数字**（统计一律现算），也**不许出现真题原文**。

## 2. 方法

1. **节点**：审定表按领域分文件（数与代数、图形与几何、统计与概率…），每条给出
   知识点名、`prerequisites`、`grade`、`chapter`、`kind`（概念/运算/性质/关系/应用/思想方法）、
   `aliases`、`matchKeywords`（用于与真题关键词匹配）。
2. **存在依据**：脚本拿知识点名与其匹配词去课标条目里找，找到就把「课标版本 §领域 p页码「原文要求」」
   写进该节点的 `sources`。找不到课标依据的节点会在报告与构建输出里被标出来。
3. **前置关系（DAG）**：审定表给直接前置；脚本做环检测，并按年级/章节顺序校验方向
   （不允许"九上的知识点是七上的前置"）。
4. **真题统计**：对 183 份卷子逐题读 `questions[].keywords` 与 `domainPath`，
   与知识点的匹配词做整词匹配，得到每个知识点的：命中题数、支持卷数、题型分布、
   分值分布、分问数分布（分问数从题面里的 `（1）（2）…` 数出来，覆盖率 0.993）。
5. **共现（融合）**：同一道题里同时命中的知识点，两两成对、三三成组，统计去重后的卷数与题数；
   只统计细目节点（容器节点与"综合题"节点不参与，避免同一件事被数两遍）。低于 2 卷的组合不进产物。
6. **确定性**：`node scripts/graph-build.mjs` 连跑两次产物逐字节一致（`test/knowledge-graph.test.ts`
   里有回归项，比对的就是仓库里的文件）。

## 3. 产物

`seed/knowledge.json`

- 113 个知识点、267 条前置边；
- 年级分布：七上 11、七下 12、八上 15、八下 23、九上 26、九下 11、综合 15；
- 领域分布：数与代数 47、图形与几何 51、统计与概率 13、综合与实践 2；
- 类型分布：概念 32、性质 32、运算 19、关系 11、思想方法 10、应用 9；
- 每个节点都有 `aliases`（如「抛物线」→ 二次函数图象），所以 agent 不必一字不差写名字；
- 依据来源：课标 104 个节点、教材章节 113 个、真题统计 92 个（可重叠）。

`seed/knowledge-fusion.json`

- 113 个知识点全部有真题统计：支持卷数中位数 77 份，其中 80 个知识点有 10 份以上卷子支持；
- 400 组共现知识点对、200 组共现三元组（≥2 卷才收录）；
- 每个知识点带：常见题型、常见分值、常见分问数、**常见问法**（归纳成一句话，
  例如「画图象、由图象读性质，或判断开口方向、顶点、对称轴与增减性」）、
  **常与谁一起考**（带支持卷数）；
- 文件里的 `method` 字段写明了统计口径，避免以后有人误读数字。

## 4. 诚实清单（用之前请读）

1. **共现是"关键词 + 领域路径"层面的近似**，不是人工逐题标注。真题文本里公式大量丢失，
   所以"这道题到底考了哪几个知识点"只能靠关键词命中推断，会漏、会串。
   好在共现只用于"给方向"（哪些组合真实、常见），不用于判对错。
2. **教材没进仓库**：年级与章节顺序是人教目录的整理件（审定表里的 `chapter`），
   不是从教材正文抽的，所以"顺序依据"弱于"课标依据"。
3. **课标只到"条目"粒度**：条目原文给的是"能做什么"，把它映射成"知识点"这一步是人的判断
   （审定表），不是自动的，所以审得好不好直接决定图的质量。
4. **1 个节点标了"推断"**，构建输出里会列出来；其余都有课标与教材章节依据。
5. **综合题节点**（如「二次函数综合」）不参与共现统计，它们是"题位叫法"而不是知识点——
   它们的存在是为了兼容历史蓝图，不该被当成知识结构用。
6. **图谱不是生成器**：它给"该考什么、常和什么一起考"，题目的正确性仍然只能来自构造与闸门。

## 5. 「多知识点融合」目前做到什么程度

- **能做的**：题位可以声明多个知识点；`fusion()` 能查"这个知识点常与谁一起考、多少份卷支持"；
  `knowledge_lookup` 工具把这些交给 agent，agent 设计综合题时有真实依据（而不是自己猜组合）。
- **还没做的**：框架还不能**组合构造**——题型是一个模板 + 参数，`covers` 只是贴在它身上的标签。
  真正的融合题需要"可组合的构造片段"（图形 → 点/线/交点 → 距离/面积/最值，每步都能核对），
  再由融合数据来选择组合。这是 roadmap 上的下一步（`docs/agent/07` §5 也记着这一条）。

## 6. 怎么重建

```bash
node scripts/graph-build.mjs     # 读 data/ 里的材料，写 seed/knowledge.json 与 seed/knowledge-fusion.json
pnpm check                       # 图谱相关回归：无环、老名字仍在、search 容错、构建可复现
```

材料缺失时脚本会失败并说清缺哪个文件；仓库里已提交的产物照常能加载（图谱不依赖本地材料）。
