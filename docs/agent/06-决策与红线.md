# 06 · 决策与红线

> 这里是**动手前必读**。每条决策记：背景 → 决定 → 理由 → 被排除的选项。
> 新决策追加在末尾，编号连续；**不要删旧条目**（否决过的方案要留着，免得被重新提一遍）。

---

## ADR-0001 用 Cordis v4 做装配层

**背景**：系统形状是"一个不可变的共享制品，流经一组彼此独立、可插拔的判定者"。
**决定**：Cordis v4 负责插件挂载、依赖等待、配置校验、作用域隔离、热重载；不自己造框架。
**理由**：它的原语与需求一一对应（`inject` / `Config` / `ctx.effect` / `waterfall` / `isolate` / loader+HMR）。
**排除**：裸脚本 + if-else（会毁掉"可插拔命题组"这个核心叙事）；引入第二个框架。

## ADR-0002 产品形态：`npx` 启动的自有服务 + 深度定制界面

**背景**：曾讨论"给现成 harness 写插件/MCP"。
**决定**：本项目**自己就是那个产品**——`npx examharness` 起服务、挂插件、开界面；界面按老师的工作方式深度定制。
**理由**：会话/流式/打断/diff/审批是 harness 公共品，可以借；但**领域视图**（卷子、题位、徽章、证据、知识网络）和**唯一写入口**借不到。
**排除**：只交付几个 MCP 工具（评审会认为薄）；从零写一个通用 harness（loop 不是本项目的创新点）。

## ADR-0003 借 loop 与模型路由，自研「资产 + 闸门 + 视图」

**决定**：agent loop、工具调用、会话持久化用 yesimagent `core`；多厂商路由与熔断用 `gateway`。
自研只有四样：**领域资产、闸门链与唯一写入口、构造器与见证、领域视图**。
**排除**：自己实现 agent 运行时、多模型网关、UI 组件库。

## ADR-0004 构造优先

**决定**：生成 = **构造 + 序列化**，两件事拆开；答案与解析的数值结论由构造/符号计算产生。
**理由**：正确性来源从"概率"变成"构造即证明"；失败时静默消失而不是输出错题；同种子可复现。
**排除**：文本优先（让模型写题再验证）、"双 AI 交叉验证"当唯一防线。

## ADR-0005 闸门不可被调度 + 题库唯一写入口

**决定**：闸门由框架挂载（waterfall 监听者），agent 既不能跳过也不能改写；题库只接受经闸门通过的写入，agent 工作区对题库**只读**。
**理由**：**验证不能被被验证者调度**。若"要不要查重/跑符号校验"由 agent 决定，正确性保证随即消失。
**排除**：把闸门做成"模型可以调用的工具"（可绕）；靠提示词要求 agent 自觉验证。

## ADR-0006 不为成本做架构

**决定**：不设单题预算刹车、不做"简单题走模板/难题走 agent"的分层路由、不做夜间队列。成本**只记录、不优化**（进评测表当一行观察值）。
**理由**：这些东西会把设计搞复杂，而对当前目标（可用率与可信度）没有贡献。
**排除**：三层成本控制、cordis-plugin-timer 定时批处理队列、按成本分级路由。
**注意**：**不要重新引入**。若将来真需要，另开 ADR 并给出数据。

## ADR-0007 agent 工作台替代固定流水线

**决定**：给 agent 一套工具 + 一个工作区，由它自己决定何时检索题库、查图谱、跑 sympy、渲图。
**理由**："需要什么"只有模型在具体题位上才知道；固定管道必须预先猜。
**排除**：固定七段流水线 + 预先取好上下文。

## ADR-0008 交互 = 会话 + 活的制品（不是向导）

**决定**：一份卷子是会话里持续被编辑的制品；支持插话、打断、局部重做、版本 diff 与回滚；有副作用的动作需显式确认。
**理由**：老师的工作方式像程序员改代码，不像填表单。
**排除**：向导式"填表 → 等待 → 出结果"。
**实现提示**：插话直接用 `ifBusy: 'join' | 'defer' | 'reject'`，不要自己造。

## ADR-0009 图形：事实层不可动 + 呈现层交给 agent + 规范校验

**决定**：
- **事实层**（坐标、平行/垂直/相等、函数表达式）只来自 `figureSpec`，agent 不得修改；
- **呈现层**（缩放、标注位置、角度弧、刻度、遮挡）交给模板渲染或子 agent 在 Python 工作区里迭代；
- 渲染产物必须带 `assertions`（几何事实 + 制图规范），并**固化归档**。
**理由**：既保住"图与条件一致"，又拿到 agent 的灵活性与可视迭代能力。
**初中制图规范（硬要求）**：不该相等的边不得画得看起来相等（"不按比例"）；图上标注数值必须等于 spec 数值；中文标注需装 CJK 字体并关闭 `axes.unicode_minus`。
**排除**：让模型直接画图（图与条件必然对不上）；纯确定性渲染（复杂图写不动）。

## ADR-0010 错因库 = 第三份资产

**决定**：选择题的每个干扰项都要挂一个**错误假设**（符号错、漏解、公式记反、单位错…），并进入错因库。
**理由**：卷子是诊断性仪器；干扰项即关于学生错误的假设。这决定产品是"出题工具"还是"诊断工具"。
**排除**：干扰项随机凑数。

## ADR-0011 独立性靠工具隔离，不靠提示词

**决定**：求解 agent 的工具集里**没有题库、没有图谱、没有见证、没有答案**。
**理由**：角色的纯粹性由装配保证，不由自觉保证。
**排除**："请在求解时不要参考答案"。

## ADR-0012 Lean 形式化缓行

**决定**：初中几何证明的 Lean/Mathlib 形式化**不进 MVP**，只写进 roadmap。
**理由**：不可及（工作量巨大，且没有现成的初等几何形式化题库）。证明题现阶段用"步骤-依据逐条核查 + 教师终审"。
**排除**：把 Lean 验证写进承诺——答辩被追问会翻车。

## ADR-0013 `preview/index.html` 只作布局参考（**已被 ADR-0023 取代：该文件已删除**）

**决定**：那张界面是静态示意，用于对齐布局与信息层级；**不是前端实现的起点**。
**理由**：正式前端要接会话、SSE、版本与证据，结构由 [03](03-数据模型与接口.md) 决定。
**排除**：在草图上直接续写产品代码。

## ADR-0014 合规与数据边界

**决定**：
- 题库素材只用**公开来源**（课程标准、官方公开发布的中高考真题等）或**自建**；
- **产品对用户默认只展示原创生成题**，不展示受版权保护的第三方原题；
- 合作资料（教师参考书等）仅作**内部风格对齐与评测**，不对外展示、不再分发；
- **人工终审必须留痕**（谁、何时、确认了什么）；agent 轨迹入库，构成审计链；
- 学生相关数据脱敏，不进入对外材料。
**理由**：赛事评审明确维护"原创性与合规性"；主动写清数据边界反而是加分项。
**排除**：爬取商业题库网站；把原题拿进演示。

## ADR-0015 界面风格：`preview/index.html` 是视觉契约（**已被 ADR-0023 取代**）

**决定**：`preview/index.html` 是项目的**视觉契约**（**不是**前端实现）。风格基线 = DeepSeek Harness / Koishi 控制台：紧凑、克制、等宽数字、单一强调色。
**文字规则（less is more + 状态与过程分离）**：
- 一行一个事实；解释性文字一律删；细节一律折叠。
- **行内只放一个状态词**（位置与颜色固定：`通过` / `待复核` / `已重做`）；**过程写成一句人话放进详情**。
- **禁止**：用符号代替词（`✗` `✓` `→` `×2`）、暴露内部术语（"回译"、插件名）、箭头串与缩写。
- 数字必须带名词——写"重做 2 次"，不写 `×2`。

**令牌来源**：**照抄 DeepSeek Harness，不要自己发明**——`dsh-client-ui-theme/lib/client.js` 的 `--dsw-*`（文字/底色/描边/状态），工具与代码块用 `--dsl-*-radius: 12px`。

**实现规则**：
- 颜色/间距/字号只走 `:root` 变量，不写死色值；明暗双主题；阶段一不引组件库。
- **字号**：正文 14px / 行高 24px；次级 13px；说明 12px；等宽行高 22px。**不许再往下缩**。
- **圆角三档**：控件 **8px**、工具块与代码块 **12px**、**用户消息气泡 22px**（气泡是胶囊，不算容器）。
- **容器不套卡片**：分隔用 4%–10% 黑的发丝线；一屏内不做卡片嵌套。
- **颜色克制**：文字用四级 label（`#0f1115` / `#43454a` / `#81858c` / `#adb2b8`）；**正常态不上色**，只有异常才用 warn `#dd8629`；主按钮**黑底白字**（DSH 的 brand-primary 是黑，不是蓝）。
- **用户消息与 agent 消息必须一眼可分**（踩过坑，别再犯）：
  - 用户 = **右对齐胶囊气泡**，`--dsw-specific-bubble`（亮 `deepseek-50 #edf3fe` / 暗 `neutral-bluish-850 #2c2c2e`），
    圆角 22px、内边距 10/16、行高 22px、`max-width: min(内容宽 × .702, 82%)`，**不带名字标签**；
  - agent = **左对齐普通文本 + 可折叠工作步骤**，不加气泡、不加底色块。
- **配方去哪找**：令牌 → `dsh-client-ui-theme/lib/client.js`；气泡与侧栏 → **`dsh-client-ui-chat/lib/client.js`**；
  代码块 → `--dsl-*-radius`。**找不到就继续翻这两个包，不要凭印象猜、也不要发明。**
**理由**：**预览长什么样，后续 agent 就照什么长**——它是防跑偏的锚点，比任何文字约定都硬。
**排除**：大字报式说明文案；卡片阴影堆叠；多强调色；在预览里塞解释长句；
正文 ≤12px 的小字号；圆角卡片与卡片嵌套。

## ADR-0016 会话上下文压缩（照 DSH 的 seam，但分层保留决策）

**背景**：命题会话会积累大量**可再生**的东西——题库命中原文、sympy 输出、渲染日志、每题多轮重做记录。上下文一满，agent 开始忘事，最贵的一种失败是**忘掉禁用清单或老师刚说的话**。

**决定**：
1. 压缩是**可选能力 seam**，不进 loop 主干：`ctx.compaction`（定义）+ `plugin-compaction-*`（后端：压力策略、剪枝、摘要）+ `/compact`（手动入口）；计量统一归 `ctx.tokenMeter` 一家。
2. **分层，不搞一刀切**：
   - **不可压（pin）**：会话约定（进度 / 班级 / 禁用清单）、蓝图、老师每条指令与**理由**、已确认与已否决的决定、未解决疑点、题位→状态映射；
   - **可摘要**：已提交题目的构造与校验过程 → 一行结果 + 引用；
   - **可剪枝**：工具输出明细 → 确定性剪枝（按 Unicode code point，不切代理对），可按引用回取。
3. **顺序**：每步之前测压力 → **先剪枝**工具结果并重测 → 仍超阈值才摘要；边界必须保持「工具调用 / 结果配对」。
4. **结构化摘要，不是散文**：必须保留 `slots`（题位状态）、`avoided`（本卷已避免的坑）、`openQuestions`——否则压缩后必然重犯同一个错，或不知道第 7 题做到哪。
5. **可见记录**：压一次就在会话里留一条行（同族行样式、标题更暗），写明保留 / 摘要 / 剪枝了什么；**不是静默丢弃**。日志留 `compaction/start | summary | end`，未配对的 start = 崩溃残留，可检测、不阻塞。
6. **证据在制品里，不在上下文里**：闸门证据、轨迹、渲染产物进 `Item` 与 `data/`（R3 冻结），压缩碰不到它们 —— **压缩永远不损害可审计性**。

**理由**：DSH 在"工具输出占满上下文"这件事上的方案是对的，照抄；但命题会话的真正命门是**决策与约束**（禁用清单、蓝图、拒绝原因），一旦被摘要就必然出错，所以必须单独成层。

**排除**：自由散文摘要（丢状态）；只按轮次粗粒度压缩（会切断工具调用与结果的配对）；把压缩做成静默行为；为了省 token 把证据搬进上下文。

## ADR-0017 检索类能力（语料 / 联网搜索）是**可配置的引导工具**

**背景**：一度把语料库只做成闸门的输入（一个 `maxSimilarity()`），**agent 手里没有检索它的手段**——
等于把"教材原文可以查、可以对比"这条参考线砍掉了。这是设计错误：[03](03-数据模型与接口.md) §3 早就写明
"同一个服务同时是引导和闸门，差别只在谁在调度"，题库与图谱都照做了，语料漏了。

**决定**：
1. 语料库长出**两副面孔（同一实现）**：
   - **引导**（agent 调度）：`corpus_search` / `corpus_read` / `corpus_compare`；
   - **闸门**（框架调度）：查重闸门调用同一个 `compare()`，按阈值判原创度。
2. **联网搜索可配置**：`plugin-websearch`，默认**关闭**；`endpoint` / `apiKey` / `limit` / `timeoutMs` 全走配置，
   密钥只从 `${VAR}` 取。
3. **工具表按配置生成**：没接语料库、没开联网搜索，agent **连工具都看不到**——
   而不是把工具塞给它再叮嘱"别用"。关掉时即使模型硬调，也只会收到明确拒绝。
4. **素材不是真值**：检索到的一切（语料原文、网页）只进模型上下文与证据，
   **不作数学真值**（R1）；题面仍要过闸门——**网上抄来的题只有查重闸门拦得住**。
5. **界面事件里不出现语料原文**：只写 id / 长度 / 来源；原文进模型上下文即可。

**理由**：agent 的能力边界就是**工具边界**；"可配置"的正确落点是**给不给这件工具**，
而不是给了之后靠提示词约束。

**排除**：把语料只当闸门输入；把检索结果当真值；工具常开再靠提示词劝阻；默认开启联网。

## ADR-0018 知识库：上传的是原料，整理交给 agent；原料不进语料

**决定**：老师上传的资料落 `data/kb/uploads/<批次>/`，**不在语料扫描目录里**；
agent 拿 `kb_list`/`kb_read`（分片）/`kb_write`/`kb_mark` 把原文里真实存在的题抽出来，
写进 `corpus/extracted/<批次>.jsonl`（记录的 `source` = `kb:<批次>`），语料库随即重扫。

**为什么**：
- 真实资料格式千奇百怪，规则式解析器写不完；"读一段、抽几条、写进去"正是 agent 擅长的；
- 原料没人核对过，**不是真值**。若让它直接进语料，查重的比较集里就混进了未经审读的文本，
  原创度凭据会变得不可信（[01](01-原理与设计.md) §素材≠真值）。

**排除**：写一个"万能导入器"；把上传的原文直接当语料；让 agent 平铺整份资料进上下文（必须分片读）。

## ADR-0019 设置是热设置，且不存密钥

**决定**：`data/settings.json` 作为覆盖层，设置页改它；模型网关/型号、联网开关、语料目录、
新建会话默认值、查重阈值**改完立刻生效**（各插件用 `ctx.get('settings')` 现读）。
真正要重启的只有装机配置（端口、插件组合），`restartRequired()` 如实上报，页面上照实显示。
密钥只从环境变量取，不入库、不上页面。

**为什么**：老师改阈值和目录是日常动作，重启服务不是；把"立即生效"和"要重启"混在一起说，是在骗用户。
阈值只能有一个来源——查重闸门写进证据的阈值必须与设置页显示的一致。

**排除**：在页面上填 API Key 并存盘；部分热改部分冷改却不明说；把阈值抄成两份常量。

## ADR-0020 agent 有工作区（在目录里干活），但**不是沙箱**

**决定**：工作台给每一轮 agent 开一个工作区目录（`data/workspaces/<会话或批次>/`）：
`in/` 原件副本 · `tmp/` agent 自己写的脚本 · `out/` 产物。
工具是 `ws_ls` / `ws_read` / `ws_write` / `ws_run`；**主 agent 与知识库整理 agent 一样有**。
`ws_run` 的规矩：argv 逐个传参（不过 shell）、可执行文件走白名单、不许工作区之外的路径、
**不许 `-c` 内联代码**（要跑的先落成脚本文件）、有超时与输出上限；
`python3`/`pip` 优先解析到仓库的虚拟环境（`.venv`，`pnpm venv` 建），**`pip install` 默认关闭**。

**为什么**：
- 真实资料是 PDF / docx / xlsx / 扫描件，格式千奇百怪，规则式解析器写不完；
  "读一段 → 抽几条 → 写成记录"正是 agent 擅长的，而**转换本身需要能跑脚本的手**；
- 跑过的东西留在目录里 → 老师能复查（可审计性）；工作区之外的路径一律拒绝 → 有边界；
- 装的库进 `.venv`，不污染系统 python。

**诚实边界**：这**不是沙箱**——没配 `-c` 只是让动作可审计，进程本身没有被隔离
（"沙箱"仍在[不做清单](#不做清单阶段一)）。`pip install` 由人决定：agent 只能如实报告"装不了，请老师跑 `pnpm venv:add X`"。

**排除**：写万能导入器；让 agent 平铺整份资料进上下文；把工作区当沙箱对外宣传。

## ADR-0021 agent 循环**看得见、可插话、可叫停**

**决定**：一轮 agent 循环不再是一个等待到底的请求。`POST /api/run`（知识库整理同理）
立刻返回 `runId`，过程走事件流：`run:started` / `run:step` / `run:done`。
界面上：

| 动作 | 接口 | 语义 |
|---|---|---|
| 插话 | `POST /api/run/interject` | 老师的话在**下一步**读进上下文（不是另起一轮） |
| 叫停 | `POST /api/run/stop` | 这一步之后不再继续，**已完成的部分保留**，状态如实标 `stopped` |
| 看进度 | `GET /api/runs` | 现在有没有在跑、跑到第几步 |

同一时刻只允许一轮（候选题表是共享状态）：再来一轮会被明确拒绝，而不是假装能并行。
插话没赶上（这一轮正好结束）时，记录里会写一行"没赶上"——不让它悄悄消失。

**为什么**：命题是"边看边改"的活。老师看到 agent 在抄原题、或方向不对，得能当场说一句；
等它跑完 8 步再重来，既浪费又不像是"在协作"。

**排除**：把循环做成黑盒（只有最终结果）；用"重新发起一轮"冒充插话；假装支持并行。

## ADR-0022 密钥只进不出；设置按路径写

**决定**（照 DeepSeek Harness 的做法）：

1. **密钥值从不进 HTTP 响应**。`GET /api/settings` 里 `model.apiKey` 只有
   `{configured, source: 'env'|'file'|'none', writable}`；写入走
   `POST /api/settings/credential`（只写不读）。原值是**整字段剥离**，不是"显示后四位"。
2. 值落 `data/credentials.json`（**0600**；别人可读就拒绝启动并打印 chmod 命令），
   设置文档里只有**引用名**（`model.apiKeyEnv`）。取值优先级：**环境变量 > 凭据文件 > 装机配置**；
   环境变量给的值不可从界面改（输入框显示"由启动环境提供（只读）"）。
3. 设置写入是**路径化补丁**：`PATCH /api/settings {ops:[{path,value}], expectedRevision}`。
   因为界面看到的是脱敏视图，整体替换会把它从没见过的密钥删掉；修订号对不上就报
   `SETTINGS_CONFLICT`，不静默覆盖。
4. 模型配置不完整就让 `configured = false` 并**说清缺什么**（API 地址/密钥/模型名），
   绝不"悄悄打 api.openai.com"。

**为什么**：本地应用的密钥同样是秘密；"掩码"意味着服务端仍然持有并放出明文片段，
而"根本不返回"更简单也更强。

**排除**：把密钥写进设置文档或提交进仓库；在界面上回显密钥；用整体替换保存设置。

## ADR-0023 界面改用 MUI（取代 ADR-0015 的手写 token 方案）

**决定**：前端用 MUI 的组件与样式（`@mui/material` + `@emotion` + `@mui/icons-material`），
主题集中在 `client/src/theme.ts`：平面优先（无阴影）、只有一档实心按钮、四种字号、
颜色只表达状态。原 `preview/index.html`（静态示意图）与手写的 `tokens.css` / 图标集**删掉**——
有了真界面，那张图就是"假的东西"。

**为什么**：手写 token 的代价越来越高（每个控件都要自己对齐焦点态、无障碍、暗色），
而 MUI 这些事已经做完了。省下的时间应该花在"这一屏该显示什么"上。

**保留的判断**（不因为换了库就变）：一屏只讲一件事；不堆卡片；不用符号当词；
状态词用中文说清（"需要你确认"而不是"needs_review"）；深浅色不是反色。

**排除**：把 MUI 当装饰库（到处 Card+阴影+彩色 Chip）；为了用组件而把界面拆成仪表盘。

## ADR-0024 读文档与 OCR 是**内置工具**，不是让模型现写脚本

**决定**：`ctx.doc` 提供 `doc_probe` / `doc_extract` / `doc_ocr` 三个工具，
背后是仓库自带的 `scripts/extract.py`（真 python，跑在 `.venv` 里）：

| 格式 | 怎么读 | 兜底 |
|---|---|---|
| 文本 / CSV / JSONL / Markdown | 直接读（chardet 猜编码） | — |
| PDF | pdfplumber 抽文字；整份没有文字层就转 OCR | pypdfium2 逐页渲染 + tesseract |
| Word / Excel | python-docx / openpyxl（段落、表格、工作表） | — |
| 图片、扫描件 | tesseract（语言包在 `data/tessdata`，`pnpm ocr:lang` 下，不需要 sudo） | 缺语言包就如实说缺哪个 |

**上传也支持二进制**：PDF / Word / 图片按 base64 原样落盘（当文本读会直接毁掉文件）。
读不了的（版式太怪、扫描太糊）工具会说明原因，模型仍可用 `ws_run` 自己写脚本接手。

**为什么**：模型每次现写转换脚本既慢又会写错，"读一段、抽几条"才该是它的事。
**排除**：内联代码当脚本用（`-c` 一律拒绝）；把"读不出来"包装成"读到了空内容"。

## ADR-0025 agent 循环**没有步数上限**（ADR-0006 的延伸）

**决定**：删掉 `maxSteps`。一轮循环停下来的方式只有两个：模型自己不再调工具，或者老师按停。
界面显示"正在做"和步数，但**不存在**"达到步数上限"这种状态。

**为什么**：步数帽子就是"给生成加个成本刹车"（ADR-0006 已否决）。
它会制造一种假象：跑到一半被砍断是正常的产品行为。真正该发生的是——
老师看见方向不对，当场说一句；或者按停，已完成的部分照常保留。

**代价（如实说）**：模型可能反复空转、烧额度。所以按停必须随手可得，而且必须**真的停**。
**排除**：用步数上限伪装成本控制；把循环做成黑盒。

## ADR-0026 数学用 LaTeX 表示，服务端渲染成 MathML

**决定**：
- **构造器**给出数学的 LaTeX（`prose.tex.stem/answer/solution`）——真值来自构造，LaTeX 也是；
- 模型只能在句子里**嵌** `$...$`，不许自己写数学；
- **服务端**把正文里的 `$...$` 与构造给的 LaTeX 一起渲染成 **MathML**（`katex` 的 mathml 输出），
  界面只显示（`stemHtml` / `answerHtml` / `tex.*Math`），前端不引数学库、不配字体；
- 导出的 HTML 里也是 MathML——浏览器原生显示，Word 也认；
- **闸门**多两条：LaTeX 编译不过 → 拦下；题面公式里的数字必须是构造参数里出现过的
  （答案与解析允许出现**推导出来的量**，多查一步会把正确的推导当成错的）。

**为什么**：数学不能是"一段看起来像数学的文字"。LaTeX 是可编译、可渲染、可比对的东西；
MathML 让"同一个公式在网页和 Word 里都还是公式"。

**排除**：让模型自由写公式再"看着像就行"；前端再引一套 KaTeX + 字体；把渲染错误的公式静默丢掉
（渲染不出来时页面会带着原文和原因显示出来）。

## ADR-0027 会话记录是一条时间线，存在会话里

**决定**：老师说的、agent 每一步、闸门的判定，都写进**会话**（`data/session-log.json`），
`GET /api/session` 带回来，界面渲染成一条时间线（一边跑一边追加，刷新不丢）。
冻结的会话不再记新行。

**为什么**：上一版按"轮次"分开显示，说一句话就换一屏——那不像对话，像日志查看器；
而且记录只在内存里，刷新就没，等于假的。记录是"这个会话发生过什么"的凭据。

**排除**：把记录当成装饰（只显示最后一次）；把记录和卷子版本混在一个文件里（写坏了会毁掉卷子）。

## ADR-0028 运行时题型：agent 写模块，**验收在隔离进程里跑**

**决定**：agent 可以在运行时**制作新题型**——写一个模块到 `constructors/`（`kind` / `covers` /
`construct(slot, seed)`），框架验收通过才注册生效。题型模块只返回**数学形状**（params / 题面 / 答案 /
解法 / `checks`），Item 由框架组装；`checks` 是**检验点**（`{expr, at, expect}`），由**框架的求值器**核对。

**为什么允许它写代码**：题型的价值在于"每道题的答案都由参数算出来"。这件事写代码最直接；
把它限制成"填模板"会砍掉表达力（复杂几何、多问综合都写不出来）。

**验收（框架侧，硬门槛）**：
1. **在独立子进程里跑**（`scripts/verify-constructor.mjs`，256 MB 上限 + 超时）；
2. 静态安全扫描：不许子进程 / 文件 / 网络 / eval——题型只许做计算；
3. 契约、规模、耗时限额（题面长度、params 数值与个数、checks 条数、单条构造耗时、模块堆占用）；
4. 30 条样题：同种子可复现、不同种子有差异（参数空间太小会被拒）；
5. **变异检验**：把参数改坏，检验点必须失败——否则判"它没有在检验任何东西"。

**踩过的坑（写下来免得再踩）**：我原以为"静态扫描 + 限额"就够了，说"这是降低风险、不是沙箱"。
结果 agent 写的模块在**顶层**跑重活，验收时把**宿主进程**直接 OOM 崩了——限额是同步检查，拦不住
`import` 时就已经执行的代码。教训：**被验收的代码必须在别的进程里跑**。

**仍然不是沙箱（如实说）**：通过验收的模块，其 `construct` 仍在主进程里执行；
真要完全隔离，得把构造也放进 worker/子进程（成本与延迟的取舍，留作 roadmap）。

## ADR-0029 隔离验收的**顺序**：先验收，再 import（这条顺序本身就是红线）

**决定**：`loadOne()` 的步骤**固定**为

1. 读源码 → 静态安全扫描（纯文本，不执行模块）；
2. **spawn 子进程验收**（子进程返回 `kind` / `covers` / `problems` / 堆占用）；
3. 只有第 2 步通过，**主进程才 `import` 它**并注册。

**为什么顺序不能反**：模块的**顶层代码在 `import` 那一刻就执行**。ADR-0028 把验收放进子进程，
但我留下了"先 import 一次读 `kind`/`covers`"的写法——于是保护等于没有：`loadAll()` 一进主进程
就把死循环模块 import 进来，**主进程自己 OOM**。真实后果有两次：一次把服务搞崩，
一次把测试进程搞崩（vitest worker 被 SIGABRT 带走，报"Worker exited unexpectedly"，
看起来像测试框架的毛病，其实是我们的顺序错了）。

**所以**：`kind` / `covers` 也由子进程的报告带回来——**不许为了读个名字先 import**。
这条顺序由测试钉住（`test/construct-dynamic.test.ts`：顶层死循环的模块必须被拒，
且**宿主进程毫发无损**）。

**顺带定下诊断规矩**：子进程被杀时来不及输出报告，就靠 stderr 上的面包屑
（`#phase:import` / `#phase:sample:N`）说清"崩在哪一步、为什么"。给 agent 的报告必须是
**能照着改的话**（"模块顶层代码在 import 那一刻内存爆了，检查循环的终止条件"），
不是"验收失败"。**报告的可行动程度，就是这个系统的可用程度。**

## ADR-0030 回译闸门要**有对照物**才核对：题型声明 goal / givens，没声明就落"待复核"

**背景（真踩的坑）**：agent 写出了能用的题型，构造出来的题也对，但题面一让模型重写（`serialize_item`）
就被回译闸门拦下，理由是"目标不一致、条件条数不一致（题面 3 条，构造 0 条）"。
原因不在题面，在**构造实例**：动态题型的 `instance.givens` 一直是空数组，
`instance.goal` 是"题面前 40 个字"——拿被截断的题干当"目标"去核对，等于拿假对照物判卷。
它连改了六轮模块都没用（那根本不是模块能修的），白白烧了一轮。

**决定**：

1. **题型模块可以（也建议）声明 `goal` / `givens`**：`goal` 是"题目要求什么"，`givens` 是"题面显式给出的条件"。
   回译闸门就是拿它们核对"有没有写漏、写歪"。**没声明 `goal` 就不再拿题面前 40 字冒充它**。
2. **核对不了的项不假装核对**：构造实例没声明目标/条件时，回译出来的题面**判 `needsReview`**
   （`lifecycle = needs_review`，只能由老师签字升级，见 R4）。既不假通过，也不冤枉题面。
3. **题面公式只有题型声明了才算数**：动态组装里原写作 `tex.stem = answerTex ?? stem`——
   于是"题面公式"里放的是**答案**，卷面上会把答案印在题干位置。没声明 `stemTex` 就不放这个字段
   （题面本身照常渲染）。
4. **结构性数字不算题目数据**：回译闸门核对"题面公式里的数字必须来自构造参数"时，
   先去掉分问标号（`（1）（2）（3）`）与幂次（`x^{2}` 的 2）。中考解答题一定分问、公式一定有幂次，
   不放过它们就是拿误伤当严格。
5. **模板题面本来就够用**：候选题的题面是构造器给的确定性模板，`construct_item → submit_item`
   即可；`serialize_item`（模型重写题面）只在"要更像给学生看的卷子"时才用——提示词与工具说明已改。

**代价（如实说）**：没声明 `goal` 的动态题型，其题面重写后目标与条件条数**没有被验证**，
只是如实标成待复核。要让这两项真的被核对，题型必须声明它们——这是给题型作者的约束，不是给闸门的借口。

## ADR-0031 「通过验收并生效」必须真的生效：import 要带内容哈希

**背景（同一个下午踩的第三次）**：agent 按报告把题型改了、重交、验收通过，工具回话"通过验收并生效"，
但它接着出的题**还是上一版**。于是它开始怀疑蓝图、查缺口、去翻工作区——白烧一轮，
最后得出一个错的结论（"我的模块被别的构造器接管了"）。

原因：ESM **按 URL 缓存模块**。题型文件是同一个路径被反复改写，
`import(pathToFileURL(file).href)` 第二次拿到的是缓存里的旧模块——
验收（在子进程里跑，读的是磁盘上的新代码）说"通过"，主进程注册的却是旧代码。
**报告和实际行为对不上，比直接报错更坏**：它让人开始怀疑一切。

**决定**：主进程 import 时在 URL 上带**内容哈希**（`?rev=<fnv1a(源码)>`），
源码变了就是新 URL、新模块；由测试钉住（改写同一路径后重交，出题结果必须变）。

**顺带定下一条**：验收报告里"生效"这类词是有承诺的——说了生效，就必须真的生效。
写不出这个保证时，宁可说"验收通过，但注册这一步没做成"。

## ADR-0032 闸门比的是**数学事实**，不是字符串与浮点外观（根治误判）

**背景（用户拿着日志问"能不能根治"）**：界面上连着出现两条"题是对的、闸门说不"的报错——

- `答案不一致（回译得到「平均数 = 6；中位数 = 5.5；众数 = 6」，构造答案是「（1）平均数 = 6；（2）中位数 = 5.5；（3）众数 = 6」）`
  ——同一个答案，只是多带了分问序号；
- `第 1 个检验点不成立：ks*x0 + b 算出 1.000000082740371e-9，期望 0`
  ——浮点噪声比绝对容差 1e-9 大了 0.0000001%。

上一轮我把"目标/条件"改成内容相似（ADR-0030），但**答案还在比字符串、数值还在用绝对容差**——
病根没除：只要判据是"外观"，误判就会换个地方再冒出来。

**决定（三条，都进 core，验收脚本与闸门共用同一套规则）**：

1. **答案按"值"比**：`sameAnswer()` 把两边解析成
   **数值多重集**（分数按值算，如 `5/12 → 0.4166…`）+ 字母集合；
   数值必须一致、构造侧的字母必须都被包含。
   于是分问序号（（1）（2））、名称（"平均数 ="）、分隔符、书写顺序都不再误伤；
   而 `x = 2` vs `x = 3`、`5/12` vs `5/13` 照样拦下。
2. **数值比较一律用相对容差**：`closeEnough(a, b, tol) = |a−b| ≤ tol·max(1, |a|, |b|)`，
   默认 `tol = 1e-6`（`verify-symbolic.tolerance` 可收紧）。绝对容差对量级大的正确结果必然误判。
   `core/expr.ts`、符号闸门、`scripts/verify-constructor.mjs` 的变异检验**用同一个函数**——
   以前三处各写各的阈值，就是"同一件事三套标准"。
3. **接受"说不准"，但不接受"假装验过"**：语义上像但不确定的（目标相似度 0.35–0.6）
   落 `needsReview` 交老师看；只有明确不一致才判错。

**为什么这才是根治**：判据从"字符串相等/绝对差"换成"**值相等/相对差**"之后，
误判的**来源**消失了，而不是逐个补丁绕过它。凡是"比对"的地方都按这条办：
先问"我在比什么数学事实"，再决定怎么比。

**回归测试**（都是真实被拦下来的例子）：分问序号/名称差异必须放行；
`5/12` vs `5/13` 必须拦下；1e-9 量级噪声**走完整闸门**必须放行
（先把旧判据放回去确认测试会红，再修好）。

## ADR-0033 组卷默认**现造**：复用是显式动作，签字过的题钉住

**背景（用户当场指出的方向性错误）**："我们的目标是让 AI 现出一张原创卷，然而现在变成了
AI 补充题库里的题，然后组卷，实际上变成每次都是差不多的题，拼来拼去。"

实情确实如此：组卷的种子由 `(题位, 尝试次数)` 派生，于是**同一个题位每次都派到同一个种子**，
`paper.assemble` 一看这题已在库里就直接复用——"再出一版"其实是从库里把那批旧题捞回来。
我把 R3（产物冻结：发出去的卷不许重跑）读成了"能复用就复用"，方向就偏了。

**决定（三条）**：

1. **每次组卷给一个 nonce**（默认取当前时间），种子 = `hash(题位 | 尝试 | nonce)`。
   于是：同一次组卷内部可复现；**不同次组卷一定是新造的一批题**。
   R3 的"复用"只对**已冻结/已导出**的版本成立——那些版本存的是绑定，本来就不重跑。
2. **新卷优先用没用过的结构**：题型的结构指纹（`shapeOf`：条件 + 问法，抹掉数字）在最近三版里出现过的，
   尽量避开；实在都试过才回退。只换数字不算"新题"。
3. **老师签过字的题位钉住**：`session.assemble` 把已确认的绑定作为 `pinned` 交给组卷，
   那些题位不重造。签的是那道题，重组卷不该把它换掉。

**题库的定位随之改变**：它是**历史与证据**（这道题什么时候出过、谁签的字、查重的对照），
不是组卷的零件仓库。题库页上"用这一道"是**显式的复用动作**（界面里写明"这是复用已有的一道"，
并说清是哪张会话的哪张卷），默认路径是现造。

**验收方式**（都有测试/现场验证）：连组两次，两版**零共用**；签字一道再组，只有那道题保留、
其余全换新。

## 红线（任何人不许越过）

1. 不得让模型文本成为数学真值的来源（R1）。
2. 不得绕过唯一写入口写题库（R2）。
3. 不得让系统自动把"待复核"改成"通过"（R4）。
4. 不得对外展示或再分发受版权保护的第三方原题。
5. 不得在对外材料里承诺 Lean 验证、全自动命题、大考整卷。

多用户与权限 · 云端部署 · 沙箱 · 审批流 · 子代理编排 · 移动端 · UI 组件库 · ORM · 通用化抽象。
