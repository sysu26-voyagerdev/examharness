# docs/agent —— 给团队成员的 AI 助手读的文档

这个目录是**团队共同底稿**。它的用途只有一个：让每个人（和每个人的 AI 助手）在同一个设计上工作，
而不是各自重新发明一遍，或者把已经否决的方案又提一次。

**人是第一读者，AI 助手是第二读者。** 所以：写结论、写理由、写否定项；不写客套话。

## 三条不变量（速查）

1. 数学真值来自构造与符号计算，不来自模型文本。
2. 没经过闸门的题进不了题库（唯一写入口）。
3. 教师是命题者，AI 是命题组。

## 术语

| 词 | 含义 |
|---|---|
| **构造** | 在可控数学空间里造出一个成立的事实，答案按构造为真 |
| **见证** | witness：从条件推到目标的路径，解析、难度、定解性都从它来 |
| **序列化** | 把构造出的结构写成给人和模型读的题面（这里才用 LLM） |
| **回译** | 把题面重新解析回形式结构，与构造实例比对（往返测试） |
| **闸门** | 由框架挂载、不可被 agent 调度的判定环节（符号 / 边界 / 查重 / 图形 / 定解性） |
| **题位** | 蓝图里的一个槽位（知识点 × 认知 × 题型 × 难度 × 分值），局部重做的最小单位 |
| **待复核** | 系统不确定，必须由教师确认的状态；**不允许自动升级为通过** |
| **三份资产** | 题库（风格/覆盖/难度先验）、知识图谱（合法性/前置闭包）、错因库（干扰项/诊断） |

## 更新约定

- 改了设计 → **当次提交里同步改对应文档**，不要攒着。
- 做了架构决策（选了什么、放弃什么、为什么）→ 追加到 [`06-决策与红线.md`](06-决策与红线.md)。
- 文档与代码冲突时：**以文档为准**，然后要么改代码，要么改文档，不允许两边不一致地放着。
