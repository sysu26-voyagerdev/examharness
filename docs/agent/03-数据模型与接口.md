# 03 · 数据模型与接口

> **唯一的真相是 Schema。** 本文是团队契约：改 Schema 需要团队确认（见 [`../AGENTS.md`](../../AGENTS.md) §6）。

以下都是**草案**，字段名可改，**结构与职责不能改**——每条字段都因为某道闸门需要它才存在。

## 1. `Item`（中央制品）

```jsonc
{
  "id": "it_20261002_0001",

  // ── 唯一真相：构造出的结构。图、题面、解析都由它派生 ──
  "instance": {
    "kind": "function/parabola",
    "params": { "a": 1, "b": -4, "c": 3 },
    "objects": [{ "id": "A", "type": "point", "x": 1, "y": 0 }],
    "givens": ["经过点 A(1,0)", "经过点 B(3,0)", "顶点纵坐标 = -1"],
    "goal": { "type": "solve", "target": "解析式" }
  },

  // ── 见证：解析、难度、定解性都从这里来 ──
  "witness": {
    "steps": [
      { "n": 1, "text": "设 y = a(x-1)(x-3)", "basis": "交点式" },
      { "n": 2, "text": "顶点 x = 2，代入得 a = 1", "basis": "对称性" }
    ],
    "answer": "y = x^2 - 4x + 3",
    "auxiliary": false,            // 是否需要辅助构造（辅助线/换元）→ 难度信号
    "repr_switches": 2             // 表征转换次数（文字↔符号↔图形）→ 难度信号
  },

  // ── 序列化（LLM 唯一不可替代的位置）──
  "prose": {
    "stem": "已知抛物线 …… 求该抛物线的解析式。",
    "options": [{ "key": "A", "text": "……", "errorType": "符号错" }],
    "answerText": "y = x^2 - 4x + 3",
    "solution": ["设 y = a(x-1)(x-3)", "……"],
    "serializer": { "model": "…", "version": 3 }   // 题面可重生成，故记录版本
  },

  // ── 图形：spec 是数据，产物是渲染结果 ──
  "figure": {
    "spec": { "kind": "function-graph",
              "functions": [{ "expr": "x^2-4x+3", "domain": [-0.6, 4.6] }],
              "points": [{ "label": "A", "x": 1, "y": 0 }],
              "annotations": ["对称轴 x=2"] },
    "renderer": "template|agent",
    "artifact": "figures/it_20261002_0001.svg",
    "assertions": { "vertex": true, "roots": true, "nonMisleading": true }
  },

  // ── 证据：每个"通过"都要能回答"凭什么" ──
  "evidence": {
    "symbolic":  { "pass": true, "by": "sympy 1.13" },
    "roundtrip": { "pass": true, "diff": [] },
    "wellposed": { "pass": true, "solutions": 1 },
    "scope":     { "pass": true, "prereqClosure": ["一次函数", "配方"] },
    "figure":    { "pass": true, "intercepts": 0 },
    "dup":       { "pass": true, "maxSimilarity": 0.08 }
  },

  // ── 溯源与轨迹（可审计、可复现）──
  "provenance": {
    "constructor": "parabola/roots@v1",
    "seed": 84121,                        // 同种子可复现同一题
    "models": { "writer": "…", "solver": "…", "parser": "…" },
    "trace": "traces/it_20261002_0001.jsonl",   // agent 调了哪些工具、被拒几次
    "createdAt": "2026-10-02T21:09:41+08:00"
  },

  "lifecycle": "verified",   // draft | verified | needs_review | rejected | published | frozen
  "review": { "confirmedBy": null, "confirmedAt": null },   // 教师终审签字（R4）
  "slot": { "knowledge": ["与坐标轴交点"], "cognitive": "运用", "type": "解答", "score": 8, "difficulty": 0.58 }
}
```

**生命周期规则**

- `needs_review` **只能由人**改成 `verified`（R4）。系统不得自动升级。
- `published` / `frozen` 之后：结构、题面、图、证据、轨迹一起归档；**导出只读归档，不重跑**（R3）。

## 2. 命题蓝图（双向细目表）

```jsonc
{
  "paper": { "title": "二次函数 · 课后作业", "totalScore": 100, "minutes": 40, "class": "初三(2)班" },
  "blueprint": [
    { "knowledge": "顶点式", "cognitive": "掌握", "type": "选择", "count": 3,
      "difficulty": [0.72, 0.76], "scoreEach": 3, "minSteps": 2, "maxSteps": 4 }
  ],
  "constraints": {
    "forbidKnowledge": ["实际问题建模", "动点问题"],   // 未学 → 硬禁用
    "figureRatio": [0.2, 0.4],
    "noOverlap": true,                                 // 无冗余：同知识点同难度不得重复
    "orderBy": "difficulty"
  }
}
```

**组卷 = 在候选池上做约束求解**（覆盖 / 难度分布 / 无冗余 / 分值 / 顺序 / 时间），不是"生成 N 道题"。

## 3. 三份资产

| 服务 | 方法（草案） | 身份 |
|---|---|---|
| `ctx.bank` | `search(query, filters)` / `fewShot(slot, n)` / `fingerprint(item)` / `similarity(item)` / **`submit(item)`（唯一写入口）** | 引导 + 闸门 |
| `ctx.graph` | `prerequisites(ks)` / `closure(ks)` / `legal(ks)` / `span(ks)` / `coveredBy(paper)` | 引导 + 闸门 |
| `ctx.errormodel` | `hypotheses(knowledge)` / `distractorFor(step, h)` / `commonErrors(item)` | 引导（+ 诊断标签） |

### 知识树（graph）——真相是 `知识/*.md`（ADR-0033）

一个知识点一个文件，文件名就是节点键。**文件是真相**，`seed/knowledge.json` 只是迁移来源与兜底：

```markdown
---
title: 顶点式
order: 320
group: 函数
aliases: [配方法]
prerequisites: ["[[二次函数图象]]"]
---

y = a(x-h)² + k：顶点坐标一眼可见的那一种写法

## 学生常在这儿卡住
（老师的备注——界面改连线时**一个字都不会被碰**）
```

| 字段 | 作用 | 谁在管 |
|---|---|---|
| `title` | 显示名（缺省用键） | 界面可改 |
| `order` / `group` | 教的先后与分组，**只用于排序与画树，不参与任何判定** | 界面可改 |
| `aliases` | 老叫法；引用可以写别名，存回时统一成键 | 界面可改 |
| `prerequisites` | 前置连线，写成 `[[双链]]` | 界面可改（**增删改连线就是改这一行**） |
| 正文 | 老师的备注 | 界面可改，但改连线时不动它 |

**界面改连线 = 直接写文件**：`PUT|PATCH /api/graph/node`、`DELETE /api/graph/node`，
保存前先建整棵树验证（成环、非法文件名直接拒绝）。文件在别处被改过（Obsidian、agent），
服务要 `reload()` 才知道——**磁盘是真值，界面是视图**。

**节点键 = 文件名**：改名会让所有引用它的双链悬空，所以不允许改键；
悬空引用**保留并标红**（`diagnostics` 里的 `dangling`），不静默丢弃。

**本阶段不接判定**：`learned` 仍来自 `cordis.yml`，`order` 不驱动"已学"推导，
也没有"从 A 到 B 补齐路径"与"本卷覆盖缺口"——那要等这棵树用顺了再动（ADR-0033）。

**同一个服务同时是"引导"和"闸门"是刻意的**：模型可以随手查（引导），框架也会强制复核（闸门）。
区分标准只有一条——**谁在调度**。

**题库的正当用途 vs 禁止用途**（版权红线，见 [06](06-决策与红线.md)）：

- ✅ 风格语料（few-shot）、知识点覆盖地图、难度先验
- ❌ **把原题端给用户**（再分发）

**一句话：题库用来"模仿风格、校准覆盖"，不用来"提供答案"。** 答案由构造产生。

### 语料库（corpus）——与题库**严格分开**

| | 题库 `ctx.bank` | 语料库 `ctx.corpus` |
|---|---|---|
| 内容 | 我们自己构造、过闸门的原创题 | 真实题库 / 教材整理件 |
| 来源 | 构造器 | 外部（老师提供、公开真题……） |
| 可分发 | ✅ | ❌ 默认 `distributable: false`（ADR-0014） |
| 用途 | 组卷、复用、局部重做 | 风格对齐、难度先验、错因、**查重对照** |

**混在一起会同时毁掉"原创"叙事和查重语义**，所以物理分开、接口分开。

摄入：`.jsonl` / `.csv` / `.md` / `.txt`（纯文本、零依赖）；PDF/扫描件先 OCR（这条流水线还没写）。
放在 `corpus/`（**不进 Git**，版权+体积），格式与注意事见 [`corpus/README.md`](../../corpus/README.md)。

### 知识库（kb）——原料与语料**不能是同一堆东西**（ADR-0018）

老师上传的资料先落 `data/kb/uploads/<批次>/`，**不在语料扫描目录里**；
agent 分片读原文、抽出真实存在的题，写进 `corpus/extracted/<批次>.jsonl`，语料库随即重扫。
抽取记录的 `source` 统一写成 `kb:<批次>`，便于回溯到哪份资料。

| 概念 | 落点 | 是否进语料 | 谁写 |
|---|---|---|---|
| 原料（上传件） | `data/kb/uploads/<批次>/<文件>` | **否** | 老师上传 |
| 整理状态 | `data/kb.json`（`raw` / `ingesting` / `indexed` / `failed`） | 否 | 框架 + agent |
| 抽取结果 | `corpus/extracted/<批次>.jsonl` | **是**（`distributable: false`） | **agent**（`kb_write`） |

**为什么不让原料直接进语料**：原料没人核对过，它是素材不是真值。
混进查重的比较集，原创度凭据就不可信了。上传进语料这件事**必须经过 agent 的抽取**这一道。

### 工作区（workspace）——agent 的手脚（ADR-0020）

| 目录 | 放什么 | 谁写 | 会不会被扫进语料 |
|---|---|---|---|
| `data/workspaces/<名字>/in/` | 原件副本（PDF、docx、真题文本……） | 框架（从知识库批次铺进来） | 否 |
| `data/workspaces/<名字>/tmp/` | agent 自己写的脚本 | agent（`ws_write`） | 否 |
| `data/workspaces/<名字>/out/` | 跑出来的文本/中间产物 | agent（`ws_run`） | 否 |

工具：`ws_ls` / `ws_read`（分片）/ `ws_write` / `ws_run`（argv 数组，cwd = 工作区）。
边界：可执行文件白名单 · 不许工作区之外的路径 · **不许 `-c` 内联代码** · 超时与输出上限 ·
`python3`/`pip` 优先用 `.venv` · `pip install` 默认关闭（`pnpm venv:add X`）。
**产物是草稿不是真值**：数学结论仍然只能来自构造与符号计算（R1），闸门才是裁判（R2）。

### 数学：LaTeX 进、MathML 出（ADR-0026）

`Prose` 除了给人读的 `stem/answerText/solution`，还有一份**构造器给出的** `tex`：

```jsonc
"tex": {
  "stem":   "y = x^{2} - 4x + 3",
  "answer": "\\left|x_{2} - x_{1}\\right| = 2",
  "solution": ["(x - 1)(x - 3) = 0", "x_{1} = 1,\\quad x_{2} = 3", "..."]
}
```

接口里额外给渲染好的 MathML：`stemHtml` / `answerHtml` / `solutionHtml` / `tex.*Math`。
**界面不引数学库**，导出的 HTML 里也是 MathML（Word 认）。
闸门卡两件事：LaTeX 编译不过、题面公式里出现构造参数之外的数字。

### 会话记录（session-log）

`data/session-log.json`：每个会话一条时间线，`{ id, at, kind: user|assistant|tool|gate|verdict, text, runId? }`。
老师说的、agent 每一步、闸门判定都写进去；冻结的会话不再写。`GET /api/session` 带回来。

### 设置（settings）——热设置，密钥只进不出（ADR-0019 / ADR-0022）

`data/settings.json` 是覆盖层，设置页 `PATCH /api/settings` 改它，改完立刻生效：

| 键 | 含义 | 谁在读 |
|---|---|---|
| `model.baseUrl` / `model.model` | 模型网关与型号（**密钥只从环境变量取**） | `ctx.llm` |
| `websearch.enabled` / `websearch.endpoint` | 联网搜索开关与网关 | `ctx.websearch` |
| `corpusDirs` | 语料扫描目录（改完重扫） | `ctx.corpus` |
| `sessionDefaults` | 新建会话的默认班级/进度/蓝图 | 会话页表单 |
| `gates.*` | 查重阈值（数字重合下限、措辞上限、题库相似上限） | 查重闸门（写进证据的那一份） |

写入是**路径化补丁**（`{path, value}` + `expectedRevision`）；密钥不在设置文档里，
它在 `data/credentials.json`（0600），HTTP 只回 `{configured, source, writable}`——
**值从不回传**（`GET /api/settings` 的 `model.apiKey`）。

**原创度判定看两个指标，缺一不可**：

- `numbers`：题面数字与条件的重合度 —— **≥0.8 才算"数学上是同一道题"**；
- `wording`：措辞相似度（字符二元组）—— ≥0.55 才算"换皮"。

两者**同时成立**才判为抄原题。只看措辞会把"同一知识点、不同数值"的题全判成抄——
那会让整套流水线瘫掉（这是踩过的坑）。对外只出**数字**，不出原文。

### 语料库的两副面孔（同一实现，ADR-0017）

| 谁在调度 | 用什么 | 性质 |
|---|---|---|
| **agent**（内环，自由） | `corpus_search` / `corpus_read` / `corpus_compare` | **引导**：查、读、对比 |
| **框架**（外环，不可调度） | 查重闸门里的 `compare()` | **闸门**：按阈值判原创度 |

agent 侧工具（工作台注册，**按配置生成**）：

| 工具 | 作用 | 关键约束 |
|---|---|---|
| `corpus_search` | 按知识点/关键词检索素材，返回**摘要** | 不给全文 |
| `corpus_read` | 读某条素材全文（题干+答案） | 全文只进模型上下文；**界面事件里不出现原文** |
| `corpus_compare` | 自查是不是在抄原题（数字 + 措辞两个指标） | 与闸门同一实现 |
| `web_search` | 联网核查情境/数据/课标原文/题目是否已公开 | **默认关闭**；关掉时 agent 看不到这个工具 |

**真值边界（R1）**：检索到的一切都是**素材**，不是真值。题目正确性来自构造与符号计算；
题面一律过闸门——网上抄来的题只有查重闸门拦得住。

## 4. 闸门接口

```ts
// packages/core —— 类型化事件（声明合并，事件名与分发模式在此登记）
declare module 'cordis' {
  interface Events {
    'item:verify'(item: Item, next: () => Verdict): Verdict   // waterfall：可裁决
    'item:rejected'(payload: { item: Item; verdict: Verdict }): void  // emit：仅广播
    'paper:compose'(blueprint: Blueprint): Paper              // serial：需要返回值
  }
}

type Verdict =
  | { pass: true;  evidence: Partial<Item['evidence']> }
  | { pass: false; gate: string; reason: string; fixable: boolean; hint?: string }
```

### 回译闸门（语言保真，ADR-0004 / 01 §2）

题面由模型序列化时（`prose.serializer.model !== 'template'`）必须过回译：

```
构造实例 →（LLM 序列化）→ 题面 →（LLM 回译）→ { goal, givensCount, answer } → 与实例比对
```

三项都要一致：**目标、条件条数、答案**。不一致 → 拦下（`fixable: true`，改题面不改数学）。
这是编译器里的 round-trip 测试：它回答的不是"这题对不对"（答案由构造保证），
而是"**题面是否忠实编码了我知道为真的那个结构**"。

- 模板序列化（`model: 'template'`）**不经回译**——确定性题面不必白花一次调用；
- `strict: false` 时回译拿不到结构就留痕放行，证据里写明"本项未验成"；
- 题面是模型写的、但模型不可用 → 直接拒绝（fail closed，宁缺勿错）。

约定：

- 监听者拿 `(item, next)`：**有否决权就直接 return（短路）；只观察/放行必须 `return next()`**。
- `gate` 用插件名，便于在界面与轨迹里定位。
- `fixable: true` 表示"可以带着反馈重做"；`false` 表示结构性违规（如超纲），重做无意义。
- **闸门不得依赖 LLM 的自我判断**（R1）；允许用规则、符号计算、检索、独立求解。

## 5. 工具集与权限矩阵（独立性靠工具隔离，不靠提示词）

| 工具 | 命题 agent | 求解 agent | 说明 |
|---|---|---|---|
| `bank.search` / `graph.query` / `errormodel.*` | ✅ | ❌ | 求解员**看不到题库**，所以抄不了 |
| `construct.*` | ✅ | ❌ | |
| `sympy.*`（计算沙箱） | ✅ | ✅ | 求解员也允许算 |
| `figure.render` | ✅ | ❌ | |
| `rejections.recent`（历史拒绝原因） | ✅ | ❌ | 纯引导：读上一轮为什么被拒 |
| **`submit`（触发闸门）** | ✅ | ❌ | 由框架注册，agent 不可移除、不可改写 |

> **「工具集即权限边界」**：求解员的纯粹性不是靠"请你不要看答案"实现的，是靠它没有那个工具。

## 6. 会话状态与压缩摘要

**会话不是聊天记录，是有结构的状态**；压缩只能动"过程"，不能动"决策"（ADR-0016）。

```jsonc
{
  "pins": {                        // 不可压缩：结构化，永远在上下文里
    "progress": "九上·22章·第2课时",
    "class": "初三(2)班",
    "forbid": ["动点问题", "实际问题建模"]
  },
  "blueprint": { /* 当前版本，见 §2 */ },
  "intents": [                     // 老师的每条指令 + 理由；版本锚点在这里
    { "slot": 3, "base": "v3", "reason": "太像课本例题", "status": "done" }
  ],
  "slots": { "7": "in-progress", "9": "needs_review" },   // 题位 → 状态
  "avoided": ["漏 a>0", "干扰项重复"],                     // 本卷已避免的坑（拒绝原因归纳）
  "openQuestions": ["第 9 题图形是否可接受"],              // 未解决疑点，压缩后必须还在
  "compactions": [
    { "at": "21:12", "kept": "pins / blueprint / intents",
      "summarized": "第 1–6 题的构造与校验过程", "pruned": 12 }
  ]
}
```

**摘要必须是结构化的，不能是散文**：`slots` / `avoided` / `openQuestions` 三项丢了，agent 要么重犯同一个错，要么不知道第 7 题做到哪。

**边界**：闸门证据、轨迹、渲染产物属于**制品**（进 `Item` 与 `data/`，R3 冻结），**不进上下文**——所以压缩永远不碰证据链。
