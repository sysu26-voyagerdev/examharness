## 1. `Item`（中央制品）

```jsonc
{
  "id": "it_20261002_0001",

  // ── 唯一真相：构造出的结构。图、题面、解析都由它派生 ──
  "instance": {
    "kind": "function/parabola",
    "params": { "a": 1, "b": -4, "c": 3 },
    "objects": [{ "id": "A", "type": "point", "x": 1, "y": 0 }],
    "givens": ["经过点 A(1,0)", "经过点 B(3,0)", "顶点纵坐标 = -1"],
    "goal": { "type": "solve", "target": "解析式" }
  },

  // ── 见证：解析、难度、定解性都从这里来 ──
  "witness": {
    "steps": [
      { "n": 1, "text": "设 y = a(x-1)(x-3)", "basis": "交点式" },
      { "n": 2, "text": "顶点 x = 2，代入得 a = 1", "basis": "对称性" }
    ],
    "answer": "y = x^2 - 4x + 3",
    "auxiliary": false,            // 是否需要辅助构造（辅助线/换元）→ 难度信号
    "repr_switches": 2             // 表征转换次数（文字↔符号↔图形）→ 难度信号
  },

  // ── 序列化（LLM 唯一不可替代的位置）──
  "prose": {
    "stem": "已知抛物线 …… 求该抛物线的解析式。",
    "options": [{ "key": "A", "text": "……", "errorType": "符号错" }],
    "answerText": "y = x^2 - 4x + 3",
    "solution": ["设 y = a(x-1)(x-3)", "……"],
    "serializer": { "model": "…", "version": 3 }   // 题面可重生成，故记录版本
  },

  // ── 图形：spec 是数据，产物是渲染结果 ──
  "figure": {
    "spec": { "kind": "function-graph",
              "functions": [{ "expr": "x^2-4x+3", "domain": [-0.6, 4.6] }],
              "points": [{ "label": "A", "x": 1, "y": 0 }],
              "annotations": ["对称轴 x=2"] },
    "renderer": "template|agent",
    "artifact": "figures/it_20261002_0001.svg",
    "assertions": { "vertex": true, "roots": true, "nonMisleading": true }
  },

  // ── 证据：每个"通过"都要能回答"凭什么" ──
  "evidence": {
    "symbolic":  { "pass": true, "by": "sympy 1.13" },
    "roundtrip": { "pass": true, "diff": [] },
    "wellposed": { "pass": true, "solutions": 1 },
    "scope":     { "pass": true, "prereqClosure": ["一次函数", "配方"] },
    "figure":    { "pass": true, "intercepts": 0 },
    "dup":       { "pass": true, "maxSimilarity": 0.08 }
  },

  // ── 溯源与轨迹（可审计、可复现）──
  "provenance": {
    "constructor": "parabola/roots@v1",
    "seed": 84121,                        // 同种子可复现同一题
    "models": { "writer": "…", "solver": "…", "parser": "…" },
    "trace": "traces/it_20261002_0001.jsonl",   // agent 调了哪些工具、被拒几次
    "createdAt": "2026-10-02T21:09:41+08:00"
  },

  "lifecycle": "verified",   // draft | verified | needs_review | rejected | published | frozen
  "review": { "confirmedBy": null, "confirmedAt": null },   // 教师终审签字（R4）
  "slot": { "knowledge": ["与坐标轴交点"], "cognitive": "运用", "type": "解答", "score": 8, "difficulty": 0.58 }
}
```

**生命周期规则**

- `needs_review` **只能由人**改成 `verified`（R4）。系统不得自动升级。
- `published` / `frozen` 之后：结构、题面、图、证据、轨迹一起归档；**导出只读归档，不重跑**（R3）。

## 2. 命题蓝图（双向细目表）

```jsonc
{
  "paper": { "title": "二次函数 · 课后作业", "totalScore": 100, "minutes": 40, "class": "初三(2)班" },
  "blueprint": [
    { "knowledge": "顶点式", "cognitive": "掌握", "type": "选择", "count": 3,
      "difficulty": [0.72, 0.76], "scoreEach": 3, "minSteps": 2, "maxSteps": 4 }
  ],
  "constraints": {
    "forbidKnowledge": ["实际问题建模", "动点问题"],   // 未学 → 硬禁用
    "figureRatio": [0.2, 0.4],
    "noOverlap": true,                                 // 无冗余：同知识点同难度不得重复
    "orderBy": "difficulty"
  }
}
```

**组卷 = 在候选池上做约束求解**（覆盖 / 难度分布 / 无冗余 / 分值 / 顺序 / 时间），不是"生成 N 道题"。

## 3. 三份资产

| 服务 | 方法（草案） | 身份 |
|---|---|---|
| `ctx.bank` | `search(query, filters)` / `fewShot(slot, n)` / `fingerprint(item)` / `similarity(item)` / **`submit(item)`（唯一写入口）** | 引导 + 闸门 |
| `ctx.graph` | `prerequisites(ks)` / `closure(ks)` / `legal(ks)` / `span(ks)` / `coveredBy(paper)` | 引导 + 闸门 |
| `ctx.errormodel` | `hypotheses(knowledge)` / `distractorFor(step, h)` / `commonErrors(item)` | 引导（+ 诊断标签） |

**同一个服务同时是"引导"和"闸门"是刻意的**：模型可以随手查（引导），框架也会强制复核（闸门）。
区分标准只有一条——**谁在调度**。

**题库的正当用途 vs 禁止用途**（版权红线，见 [06](06-决策与红线.md)）：

- ✅ 风格语料（few-shot）、知识点覆盖地图、难度先验
- ❌ **把原题端给用户**（再分发）

**一句话：题库用来"模仿风格、校准覆盖"，不用来"提供答案"。** 答案由构造产生。

## 4. 闸门接口

```ts
// packages/core —— 类型化事件（声明合并，事件名与分发模式在此登记）
declare module 'cordis' {
  interface Events {
    'item:verify'(item: Item, next: () => Verdict): Verdict   // waterfall：可裁决
    'item:rejected'(payload: { item: Item; verdict: Verdict }): void  // emit：仅广播
    'paper:compose'(blueprint: Blueprint): Paper              // serial：需要返回值
  }
}

type Verdict =
  | { pass: true;  evidence: Partial<Item['evidence']> }
  | { pass: false; gate: string; reason: string; fixable: boolean; hint?: string }
```

约定：

- 监听者拿 `(item, next)`：**有否决权就直接 return（短路）；只观察/放行必须 `return next()`**。
- `gate` 用插件名，便于在界面与轨迹里定位。
- `fixable: true` 表示"可以带着反馈重做"；`false` 表示结构性违规（如超纲），重做无意义。
- **闸门不得依赖 LLM 的自我判断**（R1）；允许用规则、符号计算、检索、独立求解。

## 5. 工具集与权限矩阵（独立性靠工具隔离，不靠提示词）

| 工具 | 命题 agent | 求解 agent | 说明 |
|---|---|---|---|
| `bank.search` / `graph.query` / `errormodel.*` | ✅ | ❌ | 求解员**看不到题库**，所以抄不了 |
| `construct.*` | ✅ | ❌ | |
| `sympy.*`（计算沙箱） | ✅ | ✅ | 求解员也允许算 |
| `figure.render` | ✅ | ❌ | |
| `rejections.recent`（历史拒绝原因） | ✅ | ❌ | 纯引导：读上一轮为什么被拒 |
| **`submit`（触发闸门）** | ✅ | ❌ | 由框架注册，agent 不可移除、不可改写 |

> **「工具集即权限边界」**：求解员的纯粹性不是靠"请你不要看答案"实现的，是靠它没有那个工具。
