# 02 · 架构与仓库结构

## 0. 产品形态（已定，见 [06](06-决策与红线.md) ADR-0002）

**一个 `npx` 启动的自有服务 + 深度定制的界面 + 两份（三份）自有资产。**

不是"给别人的 harness 写插件"，也不是一堆散装脚本。它自己就是那个产品：

```bash
npx examharness      # 起服务、挂插件、开界面
```

---

## 1. 借什么、自研什么

| 层 | 谁负责 | 说明 |
|---|---|---|
| **装配 / 生命周期** | **Cordis v4**（借） | 插件挂载、依赖等待、配置校验、作用域隔离、热重载、可逆副作用 |
| **Agent 运行时 / 模型路由** | yesimagent `core` + `gateway`（借） | turn/tool/plugin 循环；多厂商 group + 熔断；`ifBusy: join/defer/reject` 提供插话语义 |
| **领域模型** | `core`（自研，**纯库不是插件**） | Item / figureSpec / blueprint Schema、知识点图谱、类型 |
| **领域资产** | 自研 | 题库、知识图谱、错因库 |
| **闸门链 + 唯一写入口** | 自研 | 项目的正确性所在 |
| **构造器与见证** | 自研 | 数学真值的来源 |
| **领域视图（界面）** | 自研 | 卷子、题位、徽章、证据、版本 diff、知识网络视图 |

一句话：**借 loop 与装配，自研「资产 + 闸门 + 视图」。** 其余都不该自己造。

│   ├── plugin-verify-scope/    闸门：不超纲（前置闭包）
│   ├── plugin-verify-symbolic/ 闸门：算式核对（按题型独立复算；动态题型核对它声明的检验点）
│   ├── plugin-verify-dedup/    闸门：不与旧题重复、不是抄原题
│   ├── plugin-verify-roundtrip/闸门：题面忠实（回译比对：分问/条件/答案/数字）
│   ├── plugin-verify-question/ 闸门：题面得是一道题（有没有问、分问对不对、填空有没有空位）
│   ├── plugin-verify-parts/    闸门：分量够（8 分以上解答题至少两问）
│   ├── plugin-verify-options/  闸门：选择题四个选项可判（正确项必须就是构造答案）
│   ├── plugin-verify-figure/   闸门：图形规范与一致性（直角、长度标注、点不重叠）

│   ├── plugin-paper/           ctx.paper   组卷：题位 × 候选题型 × 种子，凑不齐如实报缺口
│   ├── plugin-proposals/       ctx.proposals 提案（草稿/自检/裁定）——给"改构造器"留的门
│   ├── plugin-web/             HTTP + SSE + 前端资源（界面用的投影都在这里）
│   └── plugin-workbench/       ctx.workbench agent 工作台：工具表、主循环、子 agent、运行事件

├── scripts/extract.py          读文档与 OCR（PDF / Word / Excel / 图片）——内置工具的后端
├── scripts/ocr-lang.sh         下中文语言包到 data/tessdata（`pnpm ocr:lang`，不需要 sudo）

**插件边界**只切在"真的会被单独开关/替换"的地方（闸门一个包一个、能力一个包一个）；
切太细，时间全花在接线上。现在是 27 个插件 + `core`，随能力长出来的，不是为了对齐某个数字。

### 现状

已经跑通的：`core`、图谱（113 个知识点，由 `scripts/graph-build.mjs` 从课标与 183 份真题结构统计重建）、
题库、会话（多会话/分组/版本/diff/局部重做/确认/冻结）、语料、设置、知识库（上传 + agent 整理）、
联网（默认关）、**8 道闸门**（不超纲 / 算式核对 / 不与旧题重复 / 题面忠实 / 题面是一道题 /
分量够 / 选项可判 / 图形自洽）、四个构造器插件（抛物线、代数、几何、**运行期题型**）、
图形渲染、组卷、提案、模型接入、agent 工作台（工具表 + 主循环 + 子 agent + 实时事件）、
HTTP + SSE + 界面（MUI 四页：工作台、会话、资料、设置）。

还没做的（诚实清单以 [`07`](07-应用形态与接口清单.md) §5 为准）：错因库、上下文压缩与 token 计量、
批量评测入口、真 .docx 导出、把构造也放进 worker（现在只有验收在子进程里）。

仍在文档里但**还没写**：`plugin-errors`（错因库）、`plugin-token-meter`、`plugin-compaction`、`plugin-cli`。
别以为它们已经存在。文档模型没有步数上限（ADR-0025），也没有 `preview/` 那张图（ADR-0023 已删）。

### agent 手里的工具（按配置生成）

| 工具 | 用途 |
|---|---|
| `graph_query` / `bank_stats` | 查前置闭包与越界；看题库现状 |
| `construct_item` | 按题位构造候选题 |
| `serialize_item` | 让执笔者把结构写成题面（写漏条件会被回译闸门拦下） |
| `corpus_search` / `corpus_read` / `corpus_compare` | 检索真实题库与教材素材、读全文、自查是否抄原题 |
| `kb_list` / `kb_read` / `kb_write` / `kb_mark` | 整理知识库：看清单 → 分片读原文 → 抽成结构化题目入库 → 标状态 |
| `ws_ls` / `ws_read` / `ws_write` / `ws_run` | 工作区（**主 agent 也有**）：原件副本 → 写脚本 → 跑 python3/命令行 → 产物落 out/ |
| `doc_probe` / `doc_extract` / `doc_ocr` | 读文档与 OCR：PDF / Word / Excel / 图片一次读成文字（读不了会说清为什么） |
| `web_search` | 联网核查（**可配置，默认关**） |
| `submit_item` | **唯一收尾动作**：内部必跑闸门链 |

**没接的能力，agent 连工具都看不到**——这是"可配置"的落点，不是靠提示词约束。

### 怎么加真实素材

- 题库 / 教材整理件放 `corpus/questions`、`corpus/textbooks`（**不进 Git**：版权 + 体积）；
- 知识点清单放 `corpus/knowledge`（**可以进 Git**，只用公开的课标/教材目录信息），
  在 `cordis.yml` 的 `graph.paths` 里追加文件名即可；
- 摄入格式与红线见 [`corpus/README.md`](../../corpus/README.md)；
- 老师自己传的资料走**知识库页**：原料落 `data/kb/uploads`（**不扫进语料**），
  由 agent 整理后把抽出来的题写进 `corpus/extracted`（扫进语料）。素材≠真值，别把原料直接当语料。

## 3. 启动序列

```
读 ~/.examharness/config.yml（模型、题库路径、端口）
  ↓
按 cordis.yml 挂载插件（llm → bank → graph → errors → constructors → gates → figure → paper → web）
  ↓
起 HTTP + SSE（把 agent 每一步流式推给浏览器）
  ↓
打开 / 建索引（题库、知识网络）
  ↓
自动开浏览器 → 界面就绪
```

**首启体验很关键**：`npx` 之后五分钟内能出第一份卷子——所以包里自带 `seed/`。评委当场 `npx` 就能用，也顺带兜住"演示当天 API 挂掉"的风险。

## 4. Cordis v4 机制 → 本项目用法

| 机制 | 用在哪 | 解决什么 |
|---|---|---|
| `inject` 依赖声明 | `constructors` 声明 `inject: ['llm','bank','graph']` | 加载顺序由依赖表达，不手写编排；依赖没就绪时停在 waiting 而非崩溃 |
| `Config` + standard-schema | 每个插件的题型白名单、难度区间、禁用词表 | 配错在**启动时**报 `ValidationError`，不会跑到一半才炸 |
| `ctx.effect()` 可逆副作用 | 子进程、监听器、临时目录 | 卸载/热重载自动撤销；任务可中断重跑 |
| 事件分发模式 | `emit` 进度广播、**`waterfall` 闸门链（可裁决）**、`serial` 组卷、`bail` 首个否决即停 | 闸门成为可插拔中间件链 |
| `ctx.isolate(name, label)` | 每个班级 / 每份卷子 / 每个渲染任务 | 作用域互不污染 |
| Loader + `cordis.yml` + HMR | 蓝图、题型、难度、模型档位 | 老师改配置不动代码；**现场热重载**是演示杀手锏 |
| `fiber.restart()` / `update()` | 换模型、改闸门配置 | 配置即重启，无需重启进程 |
| `cordis-plugin-timer` | 定时任务（若需要） | 不要手写 setInterval |

> v4 变化大：**只认源码与官方 API 参考**（`packages/core/src/*.ts`、官方 Context/Fiber/Registry/Service 页），别照 v3 老教程写。

## 5. 事件与闸门

- 事件名写在 `packages/core`，用 **TypeScript 声明合并**注册（`interface Events`）。
- 闸门链 = `ctx.waterfall('item:verify', item)`，每个监听者拿到 `(item, next)`：
  - 有否决权 → 直接 `return { pass: false, reason }`（短路）
  - 只观察/放行 → `return next()`
- 闸门由**独立插件**注册，插件之间互不知晓；开关只看 `cordis.yml`。
- **唯一写入口**：题库服务自己拥有写权，暴露一个 `submit` 路径（闸门通过才写）。agent 的工作区对题库**只读**。

## 6. 界面（深定制在这四块）

| 区域 | 内容 |
|---|---|
| 左 | 会话列表（哪个班的哪份卷） |
| 中 | 对话 + **命题组工作记录**：每次工具调用可展开，拒绝原因、构造参数、图缩略图都在里面 |
| 右 | **卷子画布**：题位卡片流 → 题干/图/答案/解析/徽章/证据；可切版本、看 diff、回退。另有两个页签：**知识网络**、**证据** |
| 顶 | 会话约定（进度、班级、禁用清单）+ 版本切换 + 定稿导出 |

两个让"这是专门为我做的"立刻显形的东西：

1. **工具卡片注册表**：每个领域工具自己声明怎么渲染成卡片（`bank.search` 显示命中列表、`figure.render` 直接显示图、闸门结果显示判定表）——不把 JSON 摊给老师看。
2. **知识网络视图**：把"这次考了图谱哪一片、前置闭包够不够、哪块没覆盖"画出来。图谱因此不只是内部结构，而是产品的一张脸。

界面用 MUI（ADR-0023）：主题在 `client/src/theme.ts`，页面在 `client/src/pages/`。

## 8. Cordis v4 实战要点（踩过，别再踩）

1. **插件模块命名空间本身就能当插件**：loader 取 `exports.default ?? exports`，所以包只导出 `name`/`Config`/`apply` 即可，不需要 default。
2. **`Service` 子类必须 `super(ctx, 'name')`**：构造签名是 `(ctx, name)`；漏了 name 会把 config 对象当服务名，
   `ctx.xxx` 静默变成 `undefined`——**这个 bug 只有跑起来才看得见**。
3. **`waterfall` 的调用侧要传最内层的 `next`**：签名是 `(...args: Parameters<Events[K]>)`，而事件签名里含 `next`，
   所以写 `ctx.waterfall('item:verify', item, () => ({ pass: true }))`。
4. **声明合并前必须真实导入被增强的模块**：`import '@deepseek-ai/cordis'` 那一行不能省，否则报 TS2664。
5. **TS 7 已移除 `baseUrl`**：monorepo 用 **project references**（`composite: true` + `references` + `tsc -b`）；
   不要用 `paths` 把包映射到源码（会撞 `rootDir`）。
6. **配置校验器用 schemastery**（支持 standard-schema），不要自己写一个。
7. **能力 seam：接口放 `core`，实现放插件包**。闸门只 `inject: ['bank']`，不该依赖题库包的实现，否则就是双向耦合。
8. **清理靠 fiber**：`ctx.plugin()` 返回 fiber，用 `fiber.dispose()` 撤销它的全部注册（v4 没有 `ctx.stop()`）。
9. **访问服务必须先 `inject`**：没写进 `inject` 就用 `ctx.xxx`，运行时直接抛
   `cannot get property "xxx" without inject`（框架的守卫，别绕过它去用 `ctx.get()` 蒙混）。
10. **前端是工作区包，必须先构建**：`pnpm build` 会顺带 `vite build`；
   没有 `client/dist` 时 plugin-web 会返回 503 并写明该跑哪条命令（不给白屏）。

### 前端

- 真前端在 `client/`（React 19 + Vite）；`client/src/tokens.css` 就是**视觉契约的代码形态**。
- 界面三条自觉：**不写死任何数学**（题面/图/证据都来自服务端投影）、**不作为写入口**
  （所有动作都是往会话里发一句话，入库必须过服务端的闸门链）、文字克制。
- 开发：`pnpm dev:client`（vite 5173，`/api` 代理到 8787），另开一个终端跑 `node bin.js`。
- 生产：`pnpm build && pnpm start`，界面就在 `http://<host>:8787/`。
