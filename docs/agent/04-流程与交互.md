# 04 · 流程与交互

> 本项目**不是向导**（填表 → 等待 → 拿结果），而是**会话 + 一份活的制品**。老师像程序员用 Codex 那样用它。

---

## 1. 使用流程（agent loop 版）

**① 开一个会话，像跟 Codex 讲需求。**
第一轮把背景一次说清：教学进度（九上·22 章·第 2 课时）、作业卷、40 分钟、10 题、偏易、禁用动点题、导出 Word 双栏。这些成为**会话约定**（相当于 `AGENTS.md`），后面不必重复。

**② 它开始干活，而且全程可见。**
界面是一条可展开的工作记录：`bank.search 命中 37 条`、`graph.query 前置闭包`、`sympy 构造验证通过`、`figure.render → 缩略图`、`submit 题 1 → 闸门：边界 ✅ 查重 0.06 ✅`。**点进去能看细节**：为什么拒掉一条、构造参数是多少、那张图长什么样。

**③ 产物逐条流出来，不是最后一起给。**
第 1–3 题先出来，老师**立刻**可以说"第 2 题图重画，标注别压在线上"。不必等 10 题出齐再返工。

**④ 随时插话、随时打断。**
方向不对就打断（"动点题不用禁，是我写错了"），它调整后继续，已有产物不丢。
（框架现成语义：`send(message, { ifBusy: 'join' | 'defer' | 'reject' })`——`join` = 插进当前回合的下一步。）

**⑤ 出齐之后，会话不结束——这是重点。**
继续提需求："第 3 题换综合一点的"、"再补两道解答题"、"整体难度再降一档"、"顺序调一下"。每次都是**对同一份卷子的编辑**，只重做受影响的题位，其余不动。

**⑥ 每次改动都有可读的差异。**
v1 → v2 哪几题换了、为什么换；可回退到任意版本。
**"换一道"按钮本质就是发一条"第 3 题换一道"的消息**——按钮只是预设指令的快捷方式。

**⑦ 终审 = commit。**
逐题 ✅ 或改，最后"定稿导出"。**导出 / 发布 / 写回题库这类有副作用的动作要显式确认。**

**⑧ 记录留存。**
需求、每次被闸门拒绝的原因、每处人工确认（谁、何时）构成可追溯记录。下次可以基于这次继续："还是这个班，比上次稍难。"

## 2. 为什么是这个形状：程序员写代码的类比

| 编码 | 本项目 |
|---|---|
| repo / 工作区 | **一份卷子** |
| 文件 | 一道题（题位） |
| 改一个文件 | 局部重做某一题 |
| 重构 | 换题型组合、调难度分布 |
| 类型检查 / CI / 测试 | **闸门链**（不可调度） |
| 中断 + 插话 | 打断 agent、改口 |
| diff | 版本间题目的增删改 |
| revert | 回退到 v2 |
| AGENTS.md | 会话约定（进度、班级、禁用清单） |
| commit / 发版 | 人工终审签字 + 导出 |
| 长跑后台任务 | 丢着让它跑，去看别的 |

**由这张表直接推出的四条设计要求**：

1. **制品必须可增量编辑**：卷子 = 题位 + 版本；必须支持**按题位局部重做**（改一行）与**结构改动**（重构）两种粒度。
2. **必须有会话状态**：约定、已确认决定、未解决疑点。疑点不能静默丢弃。
3. **必须有 diff / 版本 / 回滚**。
4. **必须支持插话与中断**（借用 `ifBusy` 语义，不要自己造）。

---

## 3. agent 什么时候停

不靠预算刹车（已否决，[06](06-决策与红线.md) ADR-0006），而由**结构**决定：

- 闸门全部通过 → 提交成功，该题位完成；
- 判定为**构造不可行**（参数退化、目标无解）→ 该题位作废并说明原因；
- 老师插话 / 打断 → 立即改道。

## 4. 局部重做的约束

重做某一题位时，必须**保持该题位的蓝图约束不变**（知识点 · 认知水平 · 题型 · 难度区间 · 分值）。
若老师的要求与蓝图冲突（"换一道难的"），系统应当**提出改蓝图**，而不是偷偷破坏一致性。

## 5. 长会话不会崩：上下文压缩

一份卷子要跑很多轮：每题多次重做、大量的题库命中和校验输出。上下文一满，agent 就会忘掉**禁用清单**或**老师刚说过的话**——这是最贵的一种失败。

所以压缩是**必需能力**（照 DSH 的 seam 做，见 ADR-0016），规则是**分层，不搞一刀切**：

| 层 | 内容 | 处理 |
|---|---|---|
| **不可压（pin）** | 会话约定（进度 / 班级 / 禁用清单）、蓝图、**老师的每条指令与理由**、已确认与已否决的决定、未解决疑点、题位状态 | 结构化保存，永远在上下文里 |
| **可摘要** | 已提交题目的构造与校验过程、成功且无争议的步骤 | 压成一行结果 + 引用，可按需回取 |
| **可剪枝** | 工具输出明细（命中原文、长表格、渲染日志） | **先做确定性剪枝**，不够才摘要 |

**顺序**（照抄 DSH，因为它是对的）：
每步之前测压力 → 先剪枝工具结果并重测 → 仍超阈值才摘要；边界必须保持"工具调用 / 结果配对"。

**压缩必须是可见记录**，不是静默行为。会话里留一条行（同族行样式，标题更暗）：

```
⤡  上下文已压缩  ·  压掉 12 项工具明细
   ├ 保留　会话约定 · 蓝图 · 指令与理由 · 未解决疑点
   ├ 摘要　第 1–6 题的构造与校验过程
   └ 剪枝　题库命中原文、渲染日志（可按引用回取）
```

**证据在制品里，不在上下文里**——所以压缩不影响可审计性（R3）。
手动入口：`/compact`（空闲会话强制压一次，压不动就返回空，不写入）。

## 6. 界面分区

**试卷是第一等公民**：老师要的是卷子，所以"试卷"这一栏不是卡片列表，而**一张卷面**——
标题居中、按题型分节（"一、选择题（每题 3 分，共 30 分）"）、题号连着走、选项两列、图居中；
**答案默认不显示**（一个开关切换"答案与解析"），另有打印（`@media print` 把顶栏、抽屉、
工具条、提示全都藏掉，纸上只剩题目与答题空白）。老师才能干的事（换一道 / 确认 / 状态）
收进"悬停才出现"的一小条，不占卷面。

| 区域 | 内容 |
|---|---|
| 左 | 抽屉：四个页面 + 会话列表 |
| 中 | 命题组工作记录（**同一类记录收敛成一条**，例如"入库 14 道题：S11-1 → S24-1"）+ 输入框 |
| 右 | **卷面**（见上）+ 三个页签：**知识点**（覆盖视图）、**检查**（逐题闸门明细）、**文件**（工作区文件树） |
| 顶 | 当前会话 + 模型是否就绪 + 深浅色 + 导出 |

**说人话，不露内部名字**：闸门在界面上是"算式核对 / 不超纲 / 题面忠实"，不是 roundtrip/scope；
题目 id、难度浮点尾巴、闸门英文名都不许出现在卷面上（要看得去悬停提示或折叠里）。
版本多了给"最近三版 + 一个下拉"，题位多了给"题位齐了（24 个）+ 只列缺的"。


**徽章**：`符号 ✅` `知识边界 ✅` `查重 0.08` `难度 0.72` `原创度 93%` `图形 ✅` `人工确认 · 老师 21:14` `待复核 ⚠️`。
**卷头一行小字**（信任的载体）：*本卷生成中被闸门拦下 5 次（2 次超纲 · 1 次多解 · 2 次图形误导），已自动重做。*

**界面**：用 MUI（[ADR-0023](06-决策与红线.md)），主题在 `client/src/theme.ts`。
文案按"用户要做什么"写，不写系统怎么实现；一屏只讲一件事；不用符号当词。

- 风格：DeepSeek Harness / Koishi 控制台——紧凑、克制、等宽数字、单一强调色。
- 文字：**less is more**。一行一个事实，不写解释性文案；细节折叠，不摊在表面。
- 实现：颜色/间距/字号只走 `:root` CSS 变量；明暗双主题；阶段一不引组件库。

## 7. 两个必须保留的演示瞬间

1. **故意让一道题出错，被闸门当场抓住并自动重做**——评委看"完美的结果"会怀疑，看"被抓住的错误"才相信系统是真的。
2. **现场改 `cordis.yml` 一条配置（题型/难度/禁用清单），热重载立刻生效**——比十页 PPT 都管用。
