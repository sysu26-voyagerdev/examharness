# 01 · 原理与设计

本文是整个项目的**推导过程**。读完它，你才可能在不跑偏的前提下改设计。

> 顺序是：**原理 → 推论 → 设计后果**。每一步都写清楚它排除了什么。

---

## 0. 目标函数（没有它，后面全是猜）

> **最大化「单位教师时间产出的可用原创题数」，约束是错误率低于人工命题。**

- **可用**定义为可判定：*无需改动题干/答案/解析即可直接入卷（仅可改字词）*。
- 这条排除了两件事：① 追求生成量（生成 1000 条不能用的是负资产）；② 追求全自动无人（人工复核也是成本，但**错题成本更高**）。

---

## 1. 一道数学题不是文本，是一个约束满足结构 + 一份见证

- **结构**：对象（点/线/数/函数）+ 条件（已知）+ 目标（求/证）
- **见证**：从条件推到目标的路径（解题过程本身就是它）
- **教学附加属性**：只用学过的知识、难度适当、题意无歧义、答案唯一、图形与条件一致且不误导

题面文字只是这个结构的**序列化**。这一条值得反复强调，因为它推翻了常规做法：

| | 文本优先（主流） | **构造优先（本项目）** |
|---|---|---|
| 生成 | 让模型"写出一道题" | 构造一个实例，其结论**按构造为真** |
| 验证 | 再解一遍 | 检查构造不变量 + 序列化保真 |
| 正确性来源 | 概率 | **构造即证明** |
| 失败模式 | 静默错误（最危险） | 构造失败 → 干脆不出题 |
| 可复现 | 采样随机 | 同种子 + 同模板版本 = 同一道题 |

**推论 1：生成 = 构造 + 序列化，两件事必须拆开。** 它们的验证手段完全不同：一个靠数学，一个靠语言往返。

**推论 2：验证 = 检查不变量，不是"再解一遍"。** 后者的可信度不高于生成本身。

**推论 3（范围）**：数学里**可构造性高**的是方程、函数、几何计算、概率统计计算；**低**的是应用题、开放题、几何证明。范围内的先做。
（这套判断与学段无关：**先做哪一块**由可构造性决定，不由年级决定。当前落地的材料是初中学段的。）

---

## 2. 语言层不可消除，但可以被"往返测试"

题面终究要给人读，所以 LLM 在序列化这一步**不可替代**。但它可以被严格约束：

```
构造实例 →（LLM 序列化）→ 题面 →（回译）→ 实例′ → 与实例比对
```

这是编译器里的 round-trip 测试：把"这题写得对不对"（无法回答）换成"**题面是否忠实编码了我知道为真的那个结构**"（可回答）。

**"独立求解"的真正作用**因此被重新定义：它不是验证答案（答案已由构造保证），而是验证**仅凭题面是否足够定解**：

- 条件不足 → 解不唯一或依赖额外假设 → 拒绝
- 条件冗余 / 矛盾 → 与回译结果不一致 → 拒绝

三个验证器各归其位、互不重叠：**数学真值（构造）/ 语言保真（回译）/ 信息充分（独立求解）**。

---

## 3. 试卷是测量仪器，不是题目的集合

一份卷子把学生能力映射成分数，它的规格说明书就是**双向细目表**（知识点 × 认知水平 × 难度 × 题型 × 分值）。

**推论：组卷是一个约束求解问题**——覆盖达标、难度分布达标、无冗余（不能两道题测同一个点且难度相同）、分值配平、由易到难、时间预算可控。

**因此「题目生成」与「组卷」是两个独立模块。** 这是最容易犯的架构错误：混在一起，就永远无法保证"卷子符合蓝图"，只能保证"我有 20 道题"。

**再推一步（三份资产）**：卷子既然是**诊断性**仪器，选择题的干扰项就不该是凑数的——**每个干扰项都应当是一个关于学生错误的具体假设**（符号错、漏解、公式记反、单位错、去分母漏乘……）。所以需要第三份资产：

| 资产 | 供给什么 |
|---|---|
| 题库 | 风格、覆盖地图、难度先验 |
| 知识图谱 | 合法性、前置闭包、难度跨度 |
| **错因库** | **干扰项设计、诊断价值、"这道题能测出什么"** |

错因库让产品从"出题工具"变成"诊断工具"，这是定价天花板的差别。

---

## 4. 错误成本 ≫ 效率收益 → 宁缺勿错

一道错题印进真实作业，损失的不是一次生成的钱，是教师对所有输出的信任。所以：

- 输出**三态**：`✅ 通过（证据齐全）` / `⚠️ 待复核（不确定）` / `❌ 拒绝（明确违规）`。
- **永远不允许"看起来对"进入成品。**
- **人工终审不是技术妥协，是产品定义**：教师是命题者，AI 是命题组。同时解决三件事——伦理正确、法律风险低、把不可形式化的部分（教学意图、班级适配）交还给唯一能判断的人。
- **证据链是硬要求**：每个"通过"都要能回答"凭什么"。

---

## 5. 难度不可先验得知，只能估计后校准 → 数据飞轮是唯一护城河

模型不知道"这道题对我的学生有多难"。可做的只有**用结构量估计、用学生作答校准**。

可估计的代理量（全部来自构造结构，不靠模型感觉）：见证步数、知识点跨度、表征转换次数（文字↔符号↔图形）、是否需要辅助构造（辅助线/换元）、情境熟悉度。

**长期护城河不在模型，在两样东西**：已被验证的原创题库 + 难度校准数据。

---

## 6. 由以上推出的系统形状

- **唯一中央制品 = `Item`**（结构化条目，不是"题面"），其余一切都是它的视图或派生。字段见 [03](03-数据模型与接口.md)。
- **一个 agent 工作台（内环）+ 一条闸门链（外环）**。内环自由迭代；外环不可调度。
- **提交即验证**：agent 唯一的收尾动作是提交候选，闸门被动触发，判定作为反馈回到模型。
- **局部重做优先**：改一个题位 ≠ 重出一整卷。

**为什么闸门必须不可调度**：如果"要不要查重/跑符号校验"由 agent 决定，它累了就可以不查，正确性保证随即消失。原则一句话——**验证不能被被验证者调度**（编译器与程序员的关系）。

---

## 7. 由此推出的产品与商业

**切入顺序由风险梯度决定，不由市场规模决定**：
作业卷 / 单元小卷（高频、低风险、教师试错成本低）→ 备课资源 → 大考 / 区域卷（低频、高风险、需校准数据背书）。

**卖点顺序同样由原理决定**：不是"AI 出题更快"，而是"**每一道题都能告诉你它为什么对**"。快是同行都能说的，可信是这套架构独有的。

---

## 8. 明确不做（及原因）

| 不做 | 原因 |
|---|---|
| 几何证明的 Lean 形式化 | 不可及，只在 roadmap |
| 大考整卷自动生成 | 需校准数据背书，风险梯度不允许 |
| 全自动无人工 | 违反 §4 |
| 自适应学习 / 学情诊断 | 是另一个产品 |
| 生成量指标 | 与目标函数冲突 |

## 9. 三个必须承认的不确定性

1. 主要成本在"**题型构造器要人写**"，不在 LLM——构造器开发速度决定上限；
2. **回译本身是 LLM，会错**，需要第二模型 + 规则抽查兜底；
3. 教师真正买单的可能是"快"而不是"原创"——**只能靠 beta 访谈验证，别替他们假设**。
