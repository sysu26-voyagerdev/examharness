# ExamHarness（内部叫「命题组」）

初中数学的原创命题与组卷系统。老师给一份双向细目表（下称**蓝图**），系统按题位把题目算出来、
过一遍检查、排成一份卷子，老师审、改、签字。

每道题由一个题型模块带着一组参数算出来：题干、答案、解析里的数值都来自这次构造，
因此答案可以被独立复算。模型只做一件事——把已经算好的结构写成给学生看的话
（可以带情境、换说法），写歪了会被拦下。

当前状态：**阶段一，能跑**。还缺什么写在 [`docs/agent/07`](docs/agent/07-应用形态与接口清单.md) 第 5 节，那份清单是准的。

## 跑起来

```bash
pnpm install
pnpm venv       # 给 agent 建虚拟环境（读 PDF/Word/Excel 要用，装一次就够）
pnpm ocr:lang   # 可选：下载中文 OCR 语言包（不需要 sudo）
pnpm start      # 构建 + 起服务，界面在 http://<本机 IP>:8787/
```

模型密钥两种给法：界面「设置 → API 密钥」填（落在 `data/credentials.json`，0600，页面读不回来），
或者起服务前设环境变量 `EXAMHARNESS_API_KEY`（环境变量优先，界面上只读）。

常用命令：

```bash
pnpm check                                   # lint + tsc -b + 客户端类型检查 + vitest，提交前必须全绿
pnpm dev:client                              # 前端热更（vite 5173，/api 代理到 8787），另开终端 node bin.js
bash scripts/serve.sh restart                # 起停服务（带 PID 文件；不要用 pkill，会伤到自己）
node scripts/graph-build.mjs                 # 重建知识图谱
node scripts/shot.mjs <url> <out.png>        # 界面截图（CDP；chrome --screenshot 遇到 SSE 长连接不会返回）
```

依赖：Node 20+、pnpm、Python 3。没有别的服务要起。

## 仓库里有什么

```
bin.js  cordis.yml      组合根：一行一个插件，配置在 yml 里，不在代码常量里
packages/core/          领域模型与纯库（类型、数学渲染、表达式求值、图谱算法）
packages/plugin-*/      27 个插件：图谱、题库、语料、知识库、设置、会话、组卷、图形、
                        构造器（抛物线/代数/几何/动态）、8 道闸门、模型、联网、工作台、HTTP
client/                 React + MUI 界面（工作台、会话、资料、设置）
scripts/                起服务、venv、OCR、真题统计、图谱构建、题型的隔离验收、截图
constructors/           运行期由 agent 写出来的题型模块（团队共享，随版本走）
seed/                   知识图谱（脚本生成）、示例蓝图（不含真题原文）
docs/agent/             设计文档：原理、架构、数据模型、流程、验收、决策与红线
test/                   vitest
```

界面四页用 hash 直达：`#/work`、`#/sessions`、`#/materials`、`#/settings`。
界面不引数学库：公式由服务端渲染（界面用 KaTeX 的 HTML，导出用 MathML）。

## 一道题是怎么来的

1. **题位**：蓝图的一行（考什么、题型、分值、难度、几道）。
2. **选题型**：按题位声明的知识点找覆盖它的题型；一个题位可以挂好几个题型
   （入门小题过不了分量闸门，就换多问的综合题）。
3. **构造**：题型用参数算出结构，返回题面、答案、解析，以及**检验点**
   （`{expr, at, expect}`：把 `at` 代进 `expr` 应当等于 `expect`）。
4. **组装**：Item 由框架组装（id、难度、证据、生命周期都归框架），题型碰不到这些。
5. **写题面**：默认交给模型执笔（可以写情境、换说法），但要过回译校验——分问数、条件条数、
   答案、题面里出现的每个数字，都要与构造对得上。
6. **过闸门**：题面是不是一道题、分量够不够、选择题四个选项能不能判、算式核对、不超纲、
   不与旧题重复、不是抄原题、图形自洽。任何一道不过，题就不入库。
7. **组卷**：按题位排；凑不齐的题位如实报缺口，不拿不合规的题凑数。
8. **人工终审**：`needs_review` 只能由老师签字改成通过；导出后冻结归档。

题库只有 `submit()` 一个写入口，闸门挂在它上面；agent 既不能跳过闸门，也不能绕开入口写库。

## 知识图谱是从材料里算出来的

`seed/knowledge.json`（113 个知识点、267 条前置边）与 `seed/knowledge-fusion.json`
由 `scripts/graph-build.mjs` 从真实材料确定性重建（连跑两次产物逐字节一致）：

- **课标**（2022 与 2025 修订）条目：每个节点在 `sources` 里写明依据哪一条、哪一页；
- **183 份去重真题、4571 道题**的逐题领域与关键词：题型分布、常见分问数、支持卷数；
- **共现统计**：同一道题里一起出现的知识点（400 组知识点对、200 组三元组达到 2 卷以上）。
  这是"多知识点综合题"的依据——真题里反复出现的组合就那么几十种，不是随便拼；
- 教材章节（人教目录）提供年级与顺序；教材本身没进仓库。

`scripts/graph-nodes/*.mjs` 是人工审定表（哪个知识点存在、凭什么存在、前置是谁），
统计数字一律现算，表里不许写统计结果，也不许出现真题原文。
配置里的 `learned` 写的是"**这个班学到哪儿**"，框架自动补前置闭包；闭包外的照旧判超纲。
方法与不可靠之处见 [`docs/知识图谱构建报告.md`](docs/知识图谱构建报告.md)。

## agent 在运行期也能造题型

`constructors/*.mjs` 是 agent 自己写的题型模块。写完由框架在**独立子进程**里验收：
契约字段类型、30 条样题的确定性与多样性（30 个种子至少 3 种结构，同一句式换数字会被拒）、
检验点的**变异检验**（把参数改坏它必须失败；恒等式会被判"没在检验任何东西"）、
静态安全扫描（不许文件/网络/子进程）、内存与超时上限。通过才注册生效。

主 agent 还能派子 agent（`spawn_agent`）并行做独立的事——去真题里统计问法、核对一批答案、
读书抽例题——用 `agent_status` 看进度、`agent_wait` 收结论。同一个会话同时只跑一轮，
会话之间互不影响。

**诚实边界**：验收在子进程里跑，但通过之后的构造仍在主进程里执行。这是降低风险，不是沙箱。
详见 [`docs/agent/06`](docs/agent/06-决策与红线.md)。

## 关于 AI 协作（请先读这一段）

这个项目是人与 AI 结对做的，AI 的份额很大，需要说清楚：

**人负责**：要做什么、不要做什么；四条不变量（真值来自构造、闸门不可绕、产物冻结、教师终审）；
闸门该拦什么；每一次"这不对"的判断；以及踩坑之后定下的规矩。

**AI 负责**：绝大部分代码、测试与设计文档；还有 `constructors/` 里的题型模块——
那些是**系统里的 agent** 在自己跑的时候写的，不是人手打的。提交历史里那些"修误判"的提交，
多数是 AI 先写错、被数据或用户抓住、再改对的。设计文档里记着这些真实事故
（验收顺序写反把主进程 OOM、回译拿字符串比对把对的题判错、题面只有情境没有问题却一路入库……）。

**所以**：不要默认这里的代码是对的。判断这套系统可不可信，看的是可核对的判据——
构造、检验点、闸门、测试，以及被否决方案的记录，这些都在仓库里，能自己跑。读代码之前先读
`docs/agent/01` 与 `06`，否则很容易把它改回错误的样子。

## 数据与版权

- 真题、教材、课标只在本地用，不进 Git（`data/`、`corpus/` 已忽略）。仓库里只有统计与归纳，
  没有真题原文；有测试盯着这件事。
- 来自受版权保护资料的题标记为不可对外分发；对外材料不得展示原题。
- 对外描述本项目之前，先看 [`docs/agent/06`](docs/agent/06-决策与红线.md) 的红线与不做清单。
